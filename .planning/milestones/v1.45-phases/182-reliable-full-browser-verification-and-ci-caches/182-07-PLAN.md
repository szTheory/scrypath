### Collector usage and ownership contract

The existing authenticated identity must be able to dispatch ci.yml workflow_dispatch at the owned candidate ref and read run attempts, jobs, logs and artifacts. Read-only access and gh auth status alone do not establish dispatch permission. Any separately needed push uses existing permission only on the owned branch; the collector does not push. A denied capability stops through a dynamic auth gate without new secrets, scope elevation or assumed approval; workflow token permissions stay least-privilege.

Per D-08/D-09, --output-dir names a candidate-session root, not a previously empty directory required on every invocation. The first run creates a manifest bound to repository, branch, full SHA and explicit --session-id. Later modes may join only that explicit same candidate session. Every invocation and hosted run/attempt gets an exclusive fresh subdirectory; repeated modes preserve all prior receipts and failures. Root cache-acceptance.json/full-acceptance.json are atomic indexes of manifest-listed, source-checked receipts only; they never admit loose files, foreign sessions or stale captures. A changed SHA uses a new session/root. Validate verifies the referenced session manifest, source identities, receipt paths/digests and complete attempt history; the root name alone is not evidence.
