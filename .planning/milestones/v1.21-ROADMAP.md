# Milestone v1.21: Query Toolkit And Phoenix Edge Helpers

**Status:** ✅ SHIPPED 2026-05-23
**Phases:** 80-82
**Total Plans:** 7

## Overview

`v1.21` shipped a narrow public request-edge toolkit over the existing `Scrypath.search/3` runtime. The milestone made browser-shaped search params reusable outside Phoenix, added structured edge errors, and introduced optional pure Phoenix wrappers for URL, form, and LiveView flows without creating a second runtime or exposing internal query structs as public API.

## Phases

**Goal**: carve out the small public param toolkit as a plain-data edge contract over the existing runtime without promoting internal query structs or inventing a second runtime.
**Depends on**: Phase 79

**Details:**

- [x] **Phase 80: Public query toolkit contract** (2026-05-23) — **QTK-01**, **QTK-04** — carve out the small public param toolkit as a plain-data edge contract over the existing runtime without promoting internal query structs or inventing a second runtime.

**Success criteria:**

1. A context can turn request-shaped search input into stable toolkit output and pass it to `Scrypath.search/3` without touching internal query structs.
2. The public toolkit contract is data-first and explicit enough that apps can use it outside Phoenix.
3. Search orchestration still lives in app contexts or search modules, not in toolkit helpers.
4. No schema-generated runtime verbs or new canonical runtime entrypoint appear.

**Details:**

- [x] **Phase 81: Edge normalization errors and Phoenix wrappers** (2026-05-23) — **QTK-02**, **QTK-03**, **PHX-01**, **PHX-02** — add one-time edge normalization semantics plus optional thin Phoenix helpers for controller, form, URL, and LiveView flows.

**Success criteria:**

2. Invalid input yields structured field-scoped errors that a controller or LiveView can render directly.
3. Phoenix URL/form helpers round-trip normalized state without performing search themselves.
4. LiveView flows can drive shareable search state from params and reuse the same toolkit/error semantics as non-LiveView edges.

## Milestone Summary

**Decimal Phases:**

- None.

**Key Decisions:**

- Keep `Scrypath.search/3` as the canonical runtime and stop the public toolkit at plain-data preparation plus optional edge wrappers.
- Keep `%Scrypath.Query{}` and other internal normalization/runtime structs out of the public semver contract.
- Keep Phoenix optional by publishing pure wrapper helpers rather than macros, generated controller verbs, or UI components.

**Issues Resolved:**

- Removed repeated app-level request-edge glue for browser-shaped search params.
- Added one stable structured error shape for request-edge validation across controller and LiveView flows.
- Consolidated the public docs story into one canonical request-edge guide with a focused drift gate.

**Issues Deferred:**

- Reusable composition presets and scopes over the query-toolkit layer remain future work.
- Stronger UI metadata exposure for declared filters, sorts, facets, and paging remains future work.
- The separate `v1.20` archive/code drift concern remains a reconciliation item and was not widened in this milestone.

**Technical Debt Incurred:**

- None called out by the `v1.21` milestone audit.
