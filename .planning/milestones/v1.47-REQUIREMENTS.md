# Requirements: Scrypath v1.47 Brand completion

**Defined:** 2026-11-20 (revised 2026-11-20 after the gap pass in `research/v1.47-gap-pass/`)
**Core Value:** Make search indexing feel native to Ecto and ergonomic for Phoenix teams without hiding the operational realities of keeping search in sync.

Scope source: the prepared v1.47 input (`research/v1.47-prep/` notes A to D, `reference/ROLLING-ROADMAP.md` "Post-v1.46 proposal"), carried over from the Phases 189 and 190 deferred out of v1.46, then tightened by four gap-pass reviews (E adversarial review, F autonomy stalls, G website risk, H wording and cleanup coupling). Every criterion is an executable check or a recorded decision stated as such; nothing here claims aesthetic or independent-review approval.

## v1 Requirements

### CI path classifier (Phase 188.1, plain PR first)

- [x] **CI-01**: A planning-only or docs-only PR skips the Docker browser lanes (`ecommerce-mounted` and the browser Node step) while every required context still reports. The classifier is an allowlist: the lanes run unless every changed path matches `^(\.planning/|docs/|[^/]+\.md$)`, so a new path under `brand/`, `scrypath_ops/`, `examples/`, `scripts/ci/`, `lib/`, `dev/`, `config/`, `priv/`, `language/`, `fixtures/`, `test/`, `website/`, `mix.exs`, `mix.lock` or a workflow file always runs them. `workflow_wiring_test` checks both a planted `.planning`-only diff (skips) and a diff touching any one other path (runs). Dependabot #132 is unblocked by relaxing the hardcoded `upload-artifact` SHA in `workflow_wiring_test` to a pattern, and #129 is re-run on the re-skinned base. This adds no required gate.

### Website (Phase 189)

- [x] **SITE-01**: A visitor sees the website in the new identity: the three brand fonts with their OFL texts served, the light and dark lockups, the light and dark favicons and the PNG social card, all copied or derived at build time from the pinned `brand/` files. No color literal remains in website source (CSS, HTML, JS, SVG) except the role map in `build.mjs`, which resolves each role to a `brand/tokens.json` path or, for the two dark roles with no token (`selected`, `control-edge`), to a literal held only in that map which the build asserts equals the hex named in `brand.json` (`selected` appears in a `contrastPairs` entry; `control-edge` `#8F7F94` appears only in the role sentence); the build fails if a role resolves to nothing. Roles include `on-primary` (light white, dark Night). The unthemed `favicon.svg` is not used; icon links are `favicon.ico` with `sizes`, plus the pinned themed SVG; `og:image` and `twitter:image` are absolute PNG URLs whose width and height meta equal the PNG header. Identity only: the book's site content spec (headline, single CTA, command picture) is out of scope.
- [x] **SITE-02**: The website is light by default (JS off, storage empty or throwing, device dark) and offers a Light, Dark and System picker. The picker is hidden when JavaScript is off or a storage write probe fails, remembers the choice under `scrypath-theme` (only `light`, `dark` or `system` accepted, anything else is light), follows the device in System, shows no flash of the wrong theme, has a non-color pressed indicator under `forced-colors: active`, and prints with the light tokens and lockup. `scroll-behavior: smooth` applies only under `prefers-reduced-motion: no-preference`, and transitions are 0 s under reduce. Fallback rule, decided now so nobody asks: if the picker, `theme.js`, dark tokens and their assertions are not green by the end of plan 189-02, ship light-only and amend this requirement.
- [x] **SITE-03**: The website's old palette is added to the retired-value deny-set in the same commit as the asset swap, except `d08e54`, `0c0f14` and `9aa4b6`, which also appear in `brandbook/` (4, 10 and 1 hits) and join the deny set in the Phase 191 commit that deletes `brandbook/`; the website static contract asserts those three absent from website source until then. The two `p189` allowlist entries are removed in the same commit (ceilings 7 to 5 entries and 201 to 197 hits), and the deny-list reports no retired value in website source.
- [x] **SITE-04**: `website/scripts/check.mjs` is rewritten from capture-only to computed-style, font-hash and contrast assertions for both themes, served under the production prefix (`serve.mjs --base /scrypath/`, 404 at `/`, port 0, any root-absolute `href`, `src` or CSS `url()` rejected). A dependency-free static contract runs in `core` and `repository-contracts` and takes ledger row 9 of 12 in `CONTRIBUTING.md`. Contrast is read from computed colors normalized for `color-mix()` and alpha, per pair id from `brand/brand.json` with its exact selector and background token. The website workflow's push and pull-request filters include `brand/**`, and the browser install step is measured and hardened (`channel: 'chrome'` or cache, `timeout-minutes` set) with the result recorded in `CI-EFFICIENCY.md`.
- [x] **SITE-05**: Because merging to `main` deploys, the exact-head evidence is a command, not prose: `gh api repos/szTheory/scrypath/commits/<head>/check-runs` shows `build-and-check` completed and successful with `head_sha` equal to the PR head. `build-and-check` stays a non-required check (decision recorded with its reasons and re-open trigger: a rendering regression only that job would have caught reaches `main`). The `deploy` job has its own concurrency group with `cancel-in-progress: false` and ends with a smoke step against the deployed URL (home page, one font, both lockups, the social card, all under `/scrypath/`); a `workflow_dispatch` run with a `ref` input is the documented rollback in `docs/releasing.md`.
- [x] **SITE-06**: Website copy never tells a Hex adopter to run a repo-only task: every `mix verify.adopter` mention in `website/src` (home status strip, install callout, operators step 2, docs page, `diagram.svg`) is replaced by a shipped task (`mix scrypath.status`, `failed`, `retry` or `reconcile`, whichever matches the sentence), and the website static contract fails any `mix verify.*` string in website source. The two Hex-shipped guides that also mention `verify.adopter` are a separate, contract-tested item recorded in the phase notes, not changed here. The `phase110` and `phase112` website contract tests are updated in the same commit if they pin any changed sentence.

### Wording that does not need the catalog (Phase 190)

- [x] **COPY-01**: A "Status wording" block is added to `GLOSSARY.md` first (Searchable, Pending, Queued, Retry queued, accepted, Last succeeded, each with Avoid terms), then screen copy follows it (rules in `research/brand-and-catalog/V1.46-PREP.md`): bare "Searchable" only for record or update state with an observation time; the settings row reads "Searchable fields: Used for search or Not used for search"; Pending is a row or schema aggregate and Queued is one update's step or the host-queue outcome; "Retry queued" for the host queue and "accepted" only for a Meilisearch task; "Last succeeded" everywhere; `Clear` is never shown beside a retained observation as if current. The final strings for owner-visible choices (the effect sentence, "Last succeeded" label forms) are resolved in discuss and listed in the plan. Strings pinned by the required-lane `operator.spec.ts` stay unchanged.
- [x] **COPY-02**: The label "Control room" renders in sentence case in the page title, navigation (sidebar, mobile drawer, command palette), the h1 and the "Return to Control room" link. A case-sensitive scan of every tracked file outside `.planning/` and `brand/` (explicit exception list: files already sentence case) finds no `Control Room`; every Playwright locator that matches it with `exact: true` or a case-sensitive regex is updated; a LiveView test asserts the nav link carries `aria-current="page"` on the Control room route with a title that starts "Control room".
- [x] **COPY-03**: The COPY-01 and COPY-02 guards live in one table file, `scrypath_ops/test/support/copy_rules.json`, with rows `{id, rule, glossary, forbidden, required, allowed_in, source_scope, surfaces}`. One ExUnit test in the required `ops-ui` job scans `source_scope` for `forbidden`, renders each named `surface` fixture state and asserts `required` and absence of `forbidden` (so a renamed string cannot make a `refute` vacuous). A test fails a row missing a field or with empty `surfaces`. The `ops-ui` path regex and `workflow_wiring_test` cover the scanned paths (`examples/scrypath_ecommerce/e2e/`, `GLOSSARY.md`, `DESIGN.md`), or the scan scope is limited to paths that already trigger it; the CONTRIBUTING ledger names the row this extends or adds, with trigger and churn, and the budget line equals the row count.
- [x] **COPY-04**: In `operator.spec.ts` (required lane) the promotion dialog's Cancel button is focused when it opens; ExUnit pins `data-ops-modal-initial-focus="[data-ops-modal-cancel]"` as the `ops_modal` default and on each destructive `ops_modal` (the failed-sync and index-swap confirms; the saved-search delete is an inline form and is covered by its own focus test or recorded as not covered), and pins the exact promotion-notice sentence for each `promotion_reason/1` clause.

### Cleanup (Phase 191)

- [x] **CLEAN-01**: A root-level ExUnit test in `core` asserts the demo favicon is byte-identical to `brand/assets/icon/favicon-light.svg`; the demo's own `page_controller_test.exs` keeps comparing the served file to its priv copy; the demo favicon's allowlist entry is removed.
- [x] **CLEAN-02**: The `brandbook/` readers are gone (`ui_tokens.ex`, its contract test, its `verify.phase99` `@focused_tests` entry the `verify.ui_tokens` `preferred_envs` line in `mix.exs`, and its pin and verifier-module floor in `test/release/package_contents_test.exs`) with `mix verify.repository_contracts` green on the committed state.
- [x] **CLEAN-03**: `brandbook/`, its `ci.yml` path-regex entry and its allowlist entries are removed in the same commit as their ratchet ceilings. The chain is recomputed from merged `main` after Phase 189 (expected 5 entries and 197 hits at the start, ending at 0 and 0). The three shared hexes from SITE-03 join the deny set in that commit. The deny-list, `RETIRED_DIR` and the `retire-last` tag stay in `ui-tokens.test.mjs`. Phase 191 docs never spell the retired directory path (the tripwire would flag them).
- [x] **CLEAN-04**: On ops-authored source only (`scrypath_ops/lib`, `scrypath_ops/assets/js` excluding `vendor/`, `scrypath_ops/assets/css/app.css`; never built CSS or vendor files), `ui-tokens.test.mjs` asserts every resolved `font-size` is at least 12 px (percent, em, calc and clamp rejected), no `text-[` length arbitrary value, no `uppercase` class or `text-transform: uppercase`, no whole-word `infinite`, and no `size: :xs` caller. Each has a planted failing case and an accept case (a comment, an `:infinity` atom, an `inherit` value); no gate is added; `@min_token_test_calls` and `@token_test_names` rise with the new tests in the same commit; `CONTRIBUTING.md` and `DESIGN-TOKENS.md` say these check source declarations, not rendered size.
- [x] **CLEAN-05**: A test in `brand_pin_contract_test.exs` fails if the pinned `brand/assets/icon/favicon.svg` gains `<style`, `fill=`, `currentColor` or `prefers-color-scheme`, and its message lists the workarounds to remove. A scan in `ui-tokens.test.mjs` fails if any file outside `brand/`, `.planning/` and `dev/mix/tasks/brand/update.ex` contains `icon/favicon.svg` or has the same bytes; planted cases are a text reference and a renamed byte copy, the accept case is `favicon-light.svg` served under the name `favicon.svg`. The upstream defect report is drafted in the phase record; filing it is the maintainer's step and does not gate the phase.
- [x] **CLEAN-06**: The CONTRIBUTING ledger is reworded now that its literal conditions are met: the token and deny-list row says the deny-list and directory tripwire are permanent and the parity half stays while `app.css` is a hand-kept projection of `brand/tokens.json`, the single token authority (also named in `DESIGN-TOKENS.md`); the budget sentence carries the cap of 12 forward (it names only v1.46 today); the component-contract row says v1.48 not v1.47; the favicon row's churn names the new tripwire. No cell contains a pipe, `workflow_wiring_test` stays green, and the reword lands in or after the commit that empties the allowlist.

### Standing guardrails

- [x] **GATE-02**: Every phase honors the guardrails: a second consecutive evidence-only plan forces a stop-and-decide (each phase has at most one); one full gate run per commit SHA; a stale receipt is a failed gate; no capture runs from a dirty tree. A fix to a snapshot-based gate (it reads HEAD) is committed before the gate reruns, and the first `mix verify.repository_contracts` run uses the escalated permission for `FETCH_HEAD`. A plan that touches a file the lifecycle verifier fixture copies (`contrast-checker.mjs`, `app.css`, `contrast-pairs.mjs`, `brand/tokens.json`, `brand/brand.json`) runs the whole CI Node step locally first. No preview capture or `ui:review` runs in v1.47. Squash titles are `chore(...)` or `docs(...)`, never `feat` or `fix`, because no library change ships. New required gates stay within 12 (8 used), each with a deletion trigger and expected churn. At milestone close, one read-only cross-phase check of merged `main` at the final SHA (a check, not independent or aesthetic approval) covers the other consumers of every changed asset.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Making `build-and-check` or any new check a required context | Branch protection is the maintainer's call; revisit only if a browser-only regression reaches `main` |
| Promoting a browser computed-style spec to a required lane | One observed hole does not justify gate 9 or beyond; revisit on a regression only a browser spec would catch |
| Website content changes beyond identity and the SITE-06 accuracy fix (headline, single CTA, command picture, version badge, page structure, new pages) | The full refresh is planted as SEED-004 and scoped in `research/website-refresh/`; SITE-01 is identity only |
| Ops theme default change or Bricolage in ops | Settled in v1.46: ops stays System-default, no type-scale reflow |
| Palette input focus-outline defect (v1.46 IN-07) | Needs a rendered check; owned by the v1.49 screens work |
| Catalog, storybook, fixtures, preview refresh | v1.48 |
| Hex release | The maintainer's separate explicit yes; no library change is planned |
| Aesthetic or independent-review approval claims | No person or independent reviewer is simulated |
