`v1.2` is complete in this workspace **with a known Hex-surface divergence** — see the section below.

That claim was false: the on-disk working tree contained the Phase 13 body, the full Phase 14 mix-task surface, and the Phase 15/16 verification mix tasks as uncommitted files. This is acknowledged as a one-cycle divergence; the next Hex release (0.4.0 during v1.3) will bring Hex into sync with `main`.

## Divergence Notes — Why The Gap Exists

The v1.2 execution flow completed on-disk work for phases 13-16 inside a GSD workspace, but those files were never staged/committed. When `release-please` cut `scrypath 0.3.0` via `publish-hex.yml` it checked out the `scrypath-v0.3.0` tag — a clean git checkout — so the uncommitted files did not travel to Hex. The published tarball is verifiably consistent with the git tag. The on-disk tarballs `scrypath-0.1.0/` and `scrypath-0.3.0/` that appeared in the working tree were from local `mix hex.build` runs with a dirty tree; they are not what Hex received.

Corrective commits (all on main):

- `feat(13): add operator primitives`
- `feat(14): add operator mix tasks and guides`
- `feat(15): add verify.phase13 mix task`
- `feat(16): add verify.phase14 mix task`
- `chore(ci): gate phase 13 and 14 verify tasks in CI`
- `chore: ignore local hex rebuild artifacts`
