<objective>
Make backfill (and therefore reindex) page on the full primary key, so composite-key schemas visit every row exactly once and batch results report the full cursor; fix the reindex target index primaryKey for the same schemas.

Purpose: PAGE-01/PAGE-02. Today `Backfill.primary_key/1` uses only the first key column, so a composite key `(org_id, seq)` skips rows that share a leading value across a batch boundary (pinned `{1,3}` case). `Reindex.primary_key/1` copies the bug into the Meilisearch `primaryKey` (D-17). Also lands D-02's query stripping, which LOAD-03 relies on.
Output: rewritten `Scrypath.Backfill` loop (state map, keyset builder, cursor shaping), new shared real-DB cases, and the D-17 reindex fix.
</objective>
