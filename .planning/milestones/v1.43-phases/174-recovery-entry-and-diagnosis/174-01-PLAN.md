<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser URL or LiveView event → FailedSyncLive | Public schema and work identifiers cross into server-side selection and retry decisions. |
| FailedSyncLive → host sensitive-action gate | A rendered retry control requests a host-authorized mutation. |
| FailedSyncLive receipt URL → RecoveryObservation | An opaque query lookup crosses into context-bound recovery evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-174-01 | Tampering | FailedSyncLive schema query and selector event | high | mitigate | Resolve each supplied value with OperatorSelection against the current allowlist, expose unavailable with cleared state on mismatch, and prove forged plus removed targets cannot leave a retry control or select another schema in failed_sync_live_test.exs and operator.spec.ts. |
| T-174-02 | Tampering | Recovery receipt handle and context generation | high | mitigate | Keep RecoveryObservation lookup bound to host, organization, schema, and generation; invalidate old handles and clear receipt/confirmation state when selection changes; assert stale context remains unconfirmed in failed_sync_live_test.exs. |
| T-174-03 | E | FailedSyncLive retry and delete-confirmation events | high | mitigate | Re-resolve current schema, inspect the current server row, derive FailedWork.recovery_action/1, and call Gating.gate_sensitive_action/3 at event time; assert changed eligibility and denied authorization produce no retry through the test's RecordingOban counter. |
| T-174-04 | Tampering | Backend/queue reason and metadata rendered in failed-work rows | high | mitigate | Keep values in normal HEEx interpolation and OpsUi.ops_code_block/1; never mark attacker-controlled strings safe; assert hostile tags render as text with no created script element in failed_sync_live_test.exs. |
