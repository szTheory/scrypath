# Milestone v1.1: Scrypath

**Status:** ✅ SHIPPED 2026-04-16
**Phases:** 8-10
**Total Plans:** 9

## Overview

Scrypath v1.1 did not widen the product surface. It hardened the shipped Meilisearch-first v1 library so copied docs, Meilisearch edge cases, and maintainer release checks are trustworthy enough for broader public adoption. The milestone closed the public-trust gap by tightening reliability contracts, fixing documentation hazards, and building a current launch-readiness evidence chain that preserves ownership of the earlier implementation phases.

## Phases

### Phase 8: Reliability and Contract Hardening

**Goal:** Remove edge-case ambiguity from the Meilisearch and shared sync contracts so hard failures stay explicit and no-op paths are well-defined.
**Depends on:** None
**Plans:** 3 plans

Plans:

- [x] 08-01: Harden Meilisearch task normalization and inline wait contract tests
- [x] 08-02: Define shared empty-batch no-op semantics and telemetry coverage
- [x] 08-03: Keep live reliability verification narrow and add the phase verification Mix task

**Details:**
Phase 8 made malformed Meilisearch task payloads fail through explicit normalized result shapes, defined shared no-op envelopes for empty sync and delete batches, and added `mix verify.phase8` as the canonical narrow reliability gate. The live verification seam stayed explicit about its dependency on a reachable Meilisearch endpoint.

### Phase 9: Public Docs and Example Safety

**Goal:** Make the public adoption path copy-paste safe by removing misleading install guidance and hardening Phoenix examples around real request shapes.
**Depends on:** Phase 8
**Plans:** 3 plans

Plans:

- [x] 09-01: Remove misleading install guidance from the README and install-adjacent onboarding
- [x] 09-02: Harden the Phoenix JSON controller example around safe page normalization
- [x] 09-03: Align LiveView examples with realistic string-keyed attrs and add a narrow request-shape smoke test

**Details:**
Phase 9 narrowed the install contract to the real `:scrypath` dependency, replaced crash-prone JSON pagination parsing with safe normalization, and aligned the Phoenix LiveView/docs fixtures with browser-shaped nested params. The docs safety test harness now catches regressions in those public examples.

### Phase 10: Launch Verification and Release Confidence

**Goal:** Close the remaining launch-readiness gaps so maintainers can trust the release path and point to current evidence for the hardened surface.
**Depends on:** Phases 8 and 9
**Plans:** 3 plans

Plans:

- [x] 10-01: Add the thin auth-free `mix verify.phase10` gate and wire the release runbook to it
- [x] 10-02: Run the Phase 10 gate, write `10-VERIFICATION.md`, and capture the manual Hex dry-run evidence
- [x] 10-03: Create the v1.1 milestone audit and update active status files to the final evidence chain

**Details:**
Phase 10 introduced one canonical auth-free release-confidence command, locked the maintainer runbook wording to that command, wrote the Nyquist validation and verification artifacts, and closed the milestone bookkeeping around one evidence chain. The maintainer-owned Hex dry-run remained manual; the recorded authorization failure is archived as explicit operational follow-up rather than hidden inside the always-on gate.

## Milestone Summary

**Key Decisions:**

- Keep v1.1 focused on trust and hardening rather than widening the public API or backend surface.
- Preserve Meilisearch as the sole public backend while continuing to keep only an internal future-adapter seam.
- Keep the release-confidence gate auth-free and maintain the Hex publish dry-run as a maintainer-owned manual step.
- Preserve Phase 08 and Phase 09 ownership in the milestone-close evidence chain instead of re-crediting earlier hardening work to Phase 10.

**Issues Resolved:**

- Meilisearch task handling now rejects malformed payloads through explicit normalized contracts.
- Shared sync and delete entrypoints now define empty-batch behavior instead of leaving it ambiguous.
- Public README and Phoenix examples now reflect safe real-world installation and request-shape behavior.
- Maintainers now have a canonical Phase 10 verification gate, proof artifact, and milestone audit for launch-readiness review.

**Issues Deferred:**

- Live Phase 08 verification still depends on a reachable `SCRYPATH_MEILISEARCH_URL`.
- A publisher-scoped `HEX_API_KEY` is still needed for a successful Hex dry-run retry.
- The first real tagged package release remains the production confirmation path for the publish workflow.

**Technical Debt Incurred:**

- None beyond the explicit deferred operational follow-ups already captured in the v1.1 audit and verification artifact.
