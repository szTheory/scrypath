# Requirements: Scrypath v1.33 Admin UI Insane Polish

**Defined:** 2026-06-03
**Status:** Active
**Core Value:** Make search indexing feel native to Ecto and ergonomic for Phoenix teams without hiding the operational realities of keeping search in sync.

## Milestone Intent

A deliberate, owner-initiated UI/UX + design-system iteration of the `scrypath_ops` admin/ops console — the **next-level pass** building directly on v1.32's foundation (Tailwind v4 `@theme` tokens, 43 `.ops-*` components, the "quiet ops console" brand, 6 screens). This is **not** runtime product breadth. It systematically evaluates every touchpoint, tightens the design system for compounding reuse dividends, makes the information architecture task-first so users orient instantly, brings mobile-first responsiveness and restrained-but-distinctive brand motion, and focuses most depth on surfaces not already heavily iterated.

This milestone consciously overrides the documented idle/maintenance posture (`.planning/PROJECT.md`) as an explicit strategic polish wedge, decided by the owner. Evidence is screenshot-backed (before/after across light/dark × mobile/desktop × states).

### Locked design decisions
- **IA — full task-first restructure, committed by us** (no external user-testing gate): rename nav groups to job language (Triage→Recover, Probes→Explore), re-thread inter-screen links, redesign the Control Room front-door.
- **Brand — elevate within reserved**: keep the calm operator baseline; make brand moments more confident and distinctive (route/path motif, violet/copper accents, one signature page-wide verdict tone-settle). Joy through craft, not loudness.

## Requirements

### Audit harness and evidence

- [ ] **HARNESS-01**: The admin screenshot harness (`examples/scrypath_ecommerce/e2e/admin_screenshots.spec.ts`) captures every screen across the theme × viewport × state matrix (light/dark × mobile 390px/desktop 1440px × empty/populated/loading/error where applicable), producing a deterministic, re-runnable baseline.
- [ ] **SEED-01**: Named demo seed scenarios (`all_green` / `degraded` / `incident` / `empty`) drive deterministic posture so each capture exercises a screen's full state range (all status tones, every failed-sync reason class, multiple drift dimensions, zero-result + degraded search, empty + populated playbook workspace).

### Systematic audit

- [ ] **AUDIT-01**: Every touchpoint is enumerated and scored at three altitudes (element → component → page/flow) across seven dimensions (token consistency, least-surprise, a11y, responsive, brand expression, state coverage, motion appropriateness), producing one ranked, fix-class-tagged backlog with a systemic-vs-per-screen split. Findings recurring on ≥3 screens are promoted to systemic token/component fixes.

### Design-system tightening

- [x] **TOKEN-01**: The token system (`scrypath_ops/assets/css/app.css` `@theme`) is tightened — exit/dismissal easing, complete status-tone coverage in metrics, consistent shadow ladder usage, and zero raw Tailwind-step leaks in templates — with `DESIGN-TOKENS.md` kept in lockstep.
- [x] **COMP-01**: `.ops-*` components in `ops_ui.ex` are consolidated where they drift (e.g. notice/status tinted-surface internals), gaps are filled (shared loading/skeleton primitive, hover/press state parity, code-block radius), and token-step violations are removed — presentation/semantics only, no behavior change.
- [ ] **MOTION-01**: A restrained micro-animation layer (transform/opacity only, <300ms, no bounce, reduced-motion-safe) is added in service of JTBDs — the signature coherent page-wide verdict tone-settle on Refresh, exit easing on dismissals, and clickable-surface press/hover parity — expressed through the `--duration-ops-*`/`--ease-ops-*` token system.

### Information architecture and screens

- [x] **IA-01**: Navigation and the Control Room front-door speak one task-first vocabulary — nav groups renamed to jobs (Recover, Explore), inter-screen "next step" threading walks each user journey (incident, ship, explore), front-door trimmed to one ⌘K hint plus a quiet first-timer orientation affordance, three nav tiers (home doors / sidebar / palette) serving novice→power users.
- [x] **COPY-01**: UX microcopy follows the brand voice — sentence case everywhere, every empty/error state names a concrete next action (not just a state), imperative CTAs matching the final group labels, and the favored vocabulary (sync/index/drift/reconcile/backfill/retry/observe).
- [x] **RECOVER-01**: The Recover screens (posture, failed sync, sync/drift) — the densest, least-iterated data surfaces — are brought to a consistent standard for responsive behavior, full state coverage, scan path, and brand expression, with the sync/drift preflight wizard and drift chips getting the most depth.
- [x] **EXPLORE-01**: The Explore screens (search/federation, playbooks) are polished for single/multi-mode parity, zero-result and empty-workspace states, and read-only-vs-workspace clarity.

### Shell coherence and verification

- [x] **SHELL-01**: The shell chrome (header, nav, command palette, theme toggle, flash, trail/handoff) is consistent across every screen, and the trust verdict reads identically on Control Room, Posture, and Sync/Drift (the "as a unit" altitude).
- [ ] **VERIFY-01**: Tests and evidence cover the work — `mix verify.opsui`, the ScrypathOps LiveView suite, and the mounted ecommerce admin Playwright smoke stay green; a v1.32→v1.33 before/after screenshot gallery and a milestone audit against the stated intent are produced; human UAT passes.

## Out of Scope

| Feature | Reason |
|---------|--------|
| New Scrypath runtime APIs or search capabilities (autocomplete, vector, hybrid, multi-backend) | Phase 97–99 scope guard still applies; v1.33 is UI polish, not runtime breadth. |
| New admin screens or productizing OPSUI into a commercial admin surface | IA work re-threads the existing 6 screens; it does not add product surfaces. The admin UI remains a mounted, host-owned operator proof. |
| Editable saved queries / team playbooks (OPSUI-FUT-01) | Deferred to a v2+ wedge per milestone-candidates; out of this polish pass. |
| Promoting `phase105-e2e` to a required CI gate | Promotion still requires sustained stability evidence and an explicit policy change. |
| Visual-regression as a required CI gate | May be added as advisory evidence only; not a required merge gate this milestone. |
| Switching CSS architecture (e.g. to BEM) | Tailwind v4 `@theme` + daisyUI + `.ops-*` layer has momentum; double down, do not switch. |
