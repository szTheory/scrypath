# Plan 01 — Run failure enrichment and doc resolver

<objective>
Introduce a pure enrichment boundary that maps `Runner.run_validated/3` `{:error, reason}` values into a stable, JSON-serializable map (`failure_class`, `reason`, `message`, `copy`, `doc`) and resolve documentation URLs through a single `DocResolver` module backed by application config — without changing LiveView yet beyond what is required to compile new modules.
</objective>

<threat_model>
**ASVS L1 (informative):** Enrichment must not place secrets (tokens, connection strings, full playbook JSON) into `copy` or user-visible strings — allowlist only schema basename, mode, page size, query length caps as in CONTEXT D-17. Doc base URL comes from config, not user input. No new external HTTP from this plan (compile-time / test only).
</threat_model>

<action>
Create `scrypath_ops/lib/scrypath_ops/playbook/run_failure.ex` with a public function `enrich/2` (or `from_reason/2`) accepting `(reason, context_keyword)` where `context` may include `:basename`, `:schema`, `:mode` for allowlisted `copy` keys only. Implement a **module attribute registry** mapping each known `reason` (tuples and atoms used by `Runner` and stub adapter, including `{:config, :no_schema}`, `{:page_size_out_of_range, n, max}`, `:stub_hard_failure`, `:invalid_playbook_shape`) to `{failure_class :: String.t(), message :: String.t(), doc_ref :: atom(), copy_builder :: (context -> map)}`. Unknown reasons fall back to `failure_class: "unknown"`, message from safe `inspect(reason, limit: 120)`, `doc_ref: :playbook_troubleshooting`.

Create `scrypath_ops/lib/scrypath_ops/playbook/doc_resolver.ex` with `url/1` or `resolve/1` taking `doc_ref` and returning `%{primary: String.t(), related: [String.t()]}` with at most **two** related URLs. Read base from `Application.get_env(:scrypath_ops, :playbook_doc_base, default)` where **default** is the existing raw GitHub `main` base already used in `PlaybookLive` empty-state link (same string as `https://github.com/szTheory/scrypath/blob/main/` prefix) so tests need no new secret. Map each `doc_ref` to a **concrete path** under that base (e.g. `scrypath_ops/docs/playbook-schema-v1.md` with optional `#anchor`).

Add test-only or dev config key in `scrypath_ops/config/config.exs` under `import_config "#{config_env()}.exs"` only if needed; prefer `config :scrypath_ops, :playbook_doc_base, ...` in `config/test.exs` set to the same default string for determinism.

Add `scrypath_ops/test/scrypath_ops/playbook/run_failure_test.exs` asserting: (1) `{:config, :no_schema}` yields non-empty `failure_class` and `message`; (2) `doc.primary` is an `https://` URL string containing `github.com` and `playbook-schema` OR the configured test base; (3) `copy` map has only allowlisted keys present for a sample context.
</action>
