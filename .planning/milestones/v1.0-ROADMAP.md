# Milestone v1.0: Scrypath

**Status:** ✅ SHIPPED 2026-04-16
**Phases:** 1-7
**Total Plans:** 25

## Overview

Scrypath v1.0 shipped the Ecto-native search indexing core around one concrete public backend, Meilisearch, while keeping the architecture honest about sync guarantees, explicit hydration, operator workflows, and Phoenix adoption. The milestone started by establishing schema declaration and projection contracts, then added concrete sync and search paths, production async support through Oban, rebuild workflows, public-facing Phoenix docs and release automation, and finally repaired the missing verification history needed for accurate archival.

## Phases

### Phase 1: Core Contracts and API Shape

**Goal:** Define the public and internal foundations so later implementation work reinforces a stable, idiomatic product shape.
**Depends on:** None
**Plans:** 3 plans

Plans:

- [x] 01-01: Searchable schema declaration macro, validation, and runtime reflection helpers
- [x] 01-02: Projection runtime, runtime config normalization, and internal backend seam
- [x] 01-03: Public product boundary docs and architecture references

**Details:**
Phase 1 established the metadata-only `use Scrypath` contract, the reflection surface under `Scrypath.*`, explicit document projection rules, and the narrow internal backend behavior. It also fixed the public positioning early by documenting the Meilisearch-first boundary and keeping public multi-backend abstraction out of scope for v1.

## Milestone Summary

**Key Decisions:**

- Keep the public v1 backend target on Meilisearch while preserving only an internal adapter seam.
- Keep the public contract Ecto-first and context-owned, with Phoenix integrations built around that boundary.
- Support inline, Oban-backed, and manual sync modes in v1, while keeping their guarantees operationally explicit.
- Treat hydration, reindexing, and drift recovery as part of the core product contract rather than optional afterthoughts.
- Close missing milestone evidence in the original phase artifacts instead of crediting Phase 7 with feature delivery.

**Issues Resolved:**

- Established the schema declaration, projection, backend seam, sync, search, hydration, Oban, and reindex core end to end.
- Brought Phoenix docs, release automation, and package trust signals up to public-release quality.
- Repaired the missing Phase 1 and Phase 3 verification evidence and stale bookkeeping that blocked audit closure.

**Issues Deferred:**

- Advisory Phase 2 warnings around malformed Meilisearch task payload handling and empty-batch sync/delete semantics.
- Advisory Phase 6 warnings around README `Req` install guidance, JSON pagination example robustness, and LiveView string-keyed publish fixtures.
- Nyquist follow-up still missing or partial for Phases 1, 2, 3, and 6.

**Technical Debt Incurred:**

- The full test suite still has a known timeout failure in `Scrypath.Meilisearch.TasksTest`, which should be resolved in a follow-up milestone before release confidence increases further.
