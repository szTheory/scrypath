# Requirements: Scrypath

**Defined:** 2026-05-24  
**Milestone:** v1.24 — *Related-Data and Dependency Propagation*  
**Core Value:** Provide a first-class, explicit pattern for fanning out search index updates when related Ecto data changes, without introducing callback magic or hidden association walking.

## v1.24 Requirements

### Related-data propagation contracts
- [ ] **DATA-01**: The library exposes a public, explicit API (e.g., `Scrypath.sync_related/3` or an explicit fan-out struct) for defining how an association change affects child/parent search documents.
- [ ] **DATA-02**: The propagation system enforces the "no hidden magic" invariant; contexts must explicitly invoke the fan-out logic rather than relying on silent Ecto lifecycle callbacks or deep preload cascades.
- [ ] **DATA-03**: The library provides an out-of-the-box Oban worker pattern (or configurable async strategy) that durably processes related-data fan-out for larger blast radii, turning the current "temporary workaround" into a supported default.

### Execution and error handling
- [ ] **EXEC-01**: When a related-data fan-out fails midway, the system provides clear error returns or actionable logs indicating which specific records failed to sync, avoiding silent partial failures.
- [x] **EXEC-02**: Developer docs clearly define when to use inline fan-out versus durable (Oban) queueing based on blast radius and request latency. (Phase 91 plan 01 — `guides/related-data-and-reindexing.md`)

### Testing and validation
- [ ] **TEST-01**: Maintainers can easily test related-data propagation behavior in hermetic unit tests without requiring a live Meilisearch backend.
- [ ] **TEST-02**: The `verify.phase...` pattern ensures that docs contracts correctly articulate the boundary between context-owned orchestration and library-owned execution.

## Future requirements carried forward

- [ ] **AUTH-01**: Tenant-safe search access remains the next major SaaS credibility wedge.
- [ ] **FACET-UX-01**: High-cardinality facet-value search remains a narrower catalog-depth follow-on.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Silent/automatic Ecto lifecycle callbacks | Ecto callbacks for related-data fan-out create hidden footguns and race conditions. Fan-out must remain explicit. |
| Automatic detection of changed fields | Scrypath will not parse Ecto changesets to guess if an indexed field changed across associations. |
| Rebuilding the entire index for one row change | Fan-out must be targeted. If the contract changes, the operator flow (reindex) should be used instead. |
| Tenant-safe access / Authz | Scheduled for the next milestone, pending further evidence. |
