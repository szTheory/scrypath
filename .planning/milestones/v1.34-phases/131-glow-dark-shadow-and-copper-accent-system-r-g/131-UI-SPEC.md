## Token Contract: Ambient Dark Panel Depth (GLOW-01 — depth half)

### Problem being solved

Brand book §6.5: "dark mode: faint ambient shadow plus border." Phase 130 added dark
rgba shadows (`rgba(0,0,0,0.40–0.55)`) which are structurally correct but these are
vertical-lift shadows (downward), matching light mode. For dark panels that should
"read as seated depth" (pressed into the surface, not floating above it), a **dark
ambient shadow** — low-spread, inward-feeling — is needed alongside the existing border.

DK-06 finding: `.ops-panel`, `.ops-cmdk__panel`, `#flash-group > *`, `.ops-intent-card`
carry correct shadow CSS but the cream-on-dark shadow used in light reads as invisible
depth in dark when ramp was collapsed. Phase 130 replaced with rgba — this phase adds
the ambient inset quality.

### New token: `--shadow-ops-panel-dark`

Declared in the `@theme` block (both-path via D-10 pattern — hand-authored in
`[data-theme="dark"]` and `@media (prefers-color-scheme: dark) html:not([data-theme="light"])`).

```css
/* In [data-theme="dark"] + media dark block (D-10 pattern) */
--shadow-ops-panel-dark: 0 0 0 1px rgba(0,0,0,0.30), 0 1px 3px rgba(0,0,0,0.45);
```

**Visual contract:**
- The `0 0 0 1px` inset-feeling ring reads as the panel being pressed slightly into
  the surface (ambient, not floating).
- The `0 1px 3px` retains the subtle downward lift component.
- Combined with the existing `border: 1px solid color-mix(base-content 14%)`, the
  panel reads as seated depth.
- Light theme: `--shadow-ops-panel-dark` is NOT declared; light panels use the existing
  `--shadow-ops-surface` vertical lift. **Zero light regression.**

### Application sites (dark-scoped only)

Target panels per ROADMAP success criterion 1:

| Selector | Current shadow | Phase 131 change |
|----------|---------------|-----------------|
| `.ops-panel` (line ~250) | `var(--shadow-ops-surface)` | Add `var(--shadow-ops-panel-dark)` in dark override |
| `.ops-cmdk__panel` (line ~1067) | `var(--shadow-ops-overlay)` | Compose: keep overlay + add `var(--shadow-ops-panel-dark)` in dark |
| `#flash-group > *` (line ~1010) | `var(--shadow-ops-overlay)` | Compose: keep overlay + add `var(--shadow-ops-panel-dark)` in dark |
| `.ops-intent-card` (line ~851) | `var(--shadow-ops-surface)` | Add `var(--shadow-ops-panel-dark)` in dark override |

Implementation: add a dark-scoped rule block using the D-10 dual-path pattern
(`[data-theme="dark"]` + `@media (prefers-color-scheme: dark) html:not([data-theme="light"])`).

**Light gate:** `light-pixel-diff.mjs` must exit 0 "Failed pairs: 0 / 20" after this change.

## Token Contract: Quiet Violet Glow (GLOW-01 — glow half)

### Visual definition

Brand book §6.3: "quiet glow, not loud glow." Brand book §6.7: "restrained glow around
path lines." The glow is a **box-shadow aura**, never a text color, background flood, or
border fill.

### New token: `--shadow-ops-glow`

Declared in `@theme` (light value = none; dark value = the violet glow).

```css
/* @theme block */
--shadow-ops-glow: none;  /* light default — zero visual impact */

/* [data-theme="dark"] + media dark block */
--shadow-ops-glow: 0 0 8px 2px rgba(108, 92, 231, 0.30);
```

Color basis: Violet 500 `#6c5ce7` → `rgb(108, 92, 231)`.
Spread: 8px blur, 2px spread — low-spread as brand book prescribes.
Alpha: 0.30 — quiet, not loud.

### New class: `.ops-glow`

```css
.ops-glow {
  box-shadow: var(--shadow-ops-glow);
  transition: box-shadow var(--duration-ops-fast) var(--ease-ops-standard);
}
```

### Allowed application sites (exhaustive — no others)

Per ROADMAP success criterion 2: "never text, resting panels, or background floods."

| Element | Trigger | Class usage |
|---------|---------|-------------|
| `.ops-route-mark` | Always (it IS the path mark) | Add `.ops-glow` permanently in dark |
| Active nav item (`.ops-nav-item-active`) | Resting active state | Add `.ops-glow` on the active pill in dark |
| `.ops-intent-card--recommended` | Resting recommended state | Compose with existing `inset` shadow using CSS |
| Key-callout element hover state | `:hover` only | `.ops-glow` as hover modifier: `.ops-key-callout:hover { box-shadow: var(--shadow-ops-glow); }` |

**Explicitly forbidden glow targets:**
- Any text element (`p`, `span`, `h1`–`h3`, `.ops-text-*`)
- Resting `.ops-panel`, `.ops-muted-panel`, `.ops-data-card` (depth = panel-dark shadow, not glow)
- Shell background (`.ops-shell`) — already has restrained radial gradient; do NOT add glow
- `.ops-cmdk__panel` — uses `--shadow-ops-panel-dark` for depth, not glow
- `#flash-group` — uses `--shadow-ops-panel-dark` for depth, not glow

### Shell wash mobile tune (DK-10, GLOW-01 scope)

Current: `.ops-shell` radial gradient at `color-mix(primary 14%, transparent)`, `34rem` extent.
Fix: Reduce to `10%` alpha at `sm:` and below (`max-width: 640px`).

```css
@media (max-width: 640px) {
  .ops-shell {
    background:
      radial-gradient(circle at top left, color-mix(in oklch, var(--color-primary) 10%, transparent), transparent 28rem),
      linear-gradient(180deg, var(--color-base-200), var(--color-base-100));
  }
}
```

This is a dark+light simultaneous change — light shell gradient is barely perceptible
at either alpha level, so light regression risk is minimal. Run light-pixel-diff after.

## Token Contract: Copper Accent Vocabulary (COPPER-01)

### Problem being solved

DK-07: Copper (`--color-secondary`) is defined in both themes but used in only 2 places
(eyebrow `text-secondary` label in `ops_ui.ex:23`, and the route-mark gradient). The
brand prescribes 5% copper ratio. This phase introduces `.ops-copper-*` CSS classes so
copper can be applied at eyebrow labels, key-callout badges, and key-node/diagram emphasis
without touching Elixir component internals.

### Copper is never a status tone

The `.ops-copper-*` family is a **brand accent**, not a status signal. It does NOT join
the `tone_class/1` / `badge_class/1` dispatch. It carries no semantic meaning (not
info/success/warning/error/partial/running/neutral). Its use is decorative-presentational.

### Verified AA pairings

All pairings tested via WCAG 2.1 sRGB relative luminance math (matching axe-core D-12):

| Pairing | Theme | Ratio | AA verdict |
|---------|-------|-------|-----------|
| `base-content` (`#f4f1ea`) as text on copper-badge-bg (`copper 12% on surface-2`) | Dark | 12.07:1 | AA PASS |
| `base-content` (`#141923`) as text on copper-badge-bg (`copper 12% on surface-1-light`) | Light | 14.86:1 | AA PASS |
| Copper text (`#c17a3e`) on surface-2 dark (`#1b2230`) | Dark | 4.64:1 | AA PASS |
| Copper text (`#a85d2e`) on surface-1 light (`#fffdf8`) | Light | 4.84:1 | AA PASS |
| Dark text (`#0c0f14`) on copper solid fill (`#c17a3e`) | Dark | 5.59:1 | AA PASS |
| Dark text (`#141923`) on copper solid fill (`#c17a3e`) | Dark | 5.13:1 | AA PASS |

**Badge text rule:** Always use `var(--color-base-content)` for text inside copper badges
in both themes. Do NOT use `var(--color-secondary)` as badge label text (light: 4.15:1
on tinted bg — below AA threshold for small text).

**Eyebrow text rule:** `var(--color-secondary)` as text color on surface-1 background
passes AA in both themes (dark 5.13:1, light 4.84:1). The existing eyebrow at
`ops_ui.ex:23` uses `text-secondary` — this is already correct.

### New classes: `.ops-copper-eyebrow`, `.ops-copper-badge`, `.ops-copper-node`

#### `.ops-copper-eyebrow`

Eyebrow label treatment (same slot as the existing `text-secondary` utility in `ops_ui.ex:23`).
Provides the full typographic treatment as a single composable class.

```css
.ops-copper-eyebrow {
  font-size: var(--text-ops-sm);
  font-weight: 600;
  text-transform: uppercase;
  letter-spacing: 0.04em;
  color: var(--color-secondary);  /* #c17a3e dark / #a85d2e light — AA verified */
}
```

Contrast AA: dark 5.13:1 on surface-1, light 4.84:1 on surface-1. Both pass.

#### `.ops-copper-badge`

Key-callout badge. Mirrors the `.ops-badge` shape but with copper tinting instead of
status toning. Composes with `.ops-badge` for shared layout properties.

```css
.ops-copper-badge {
  border-color: color-mix(in oklch, var(--color-secondary) 44%, transparent);
  background: color-mix(in oklch, var(--color-secondary) 12%, transparent);
  color: var(--color-base-content);  /* always base-content — AA verified (12:1 dark, 14:1 light) */
}
```

Usage: `<span class="ops-badge ops-copper-badge">…</span>`

The copper badge composing with `.ops-badge` means it inherits: 1.625rem min-height,
999px border-radius, 0.625rem padding-inline, 0.75rem text, 650 weight, transition.

#### `.ops-copper-node`

Key-node / diagram-emphasis color accent. Used on icon containers or small emphasis
markers in diagram/route contexts (e.g., intent-card icon in copper rather than violet).
This is a color-only class — no layout properties.

```css
.ops-copper-node {
  color: var(--color-secondary);  /* copper — AA verified as text */
}

.ops-copper-node--fill {
  color: var(--color-secondary-content);  /* dark text on copper bg */
  background: var(--color-secondary);     /* solid copper fill */
}
```

#### Optional: `--shadow-ops-glow-copper`

A copper-tinted ambient glow for key-node hover. Declared alongside `--shadow-ops-glow`
but only in dark paths:

```css
/* [data-theme="dark"] + media dark block */
--shadow-ops-glow-copper: 0 0 6px 1px rgba(193, 122, 62, 0.25);
```

This is reserved for diagram nodes / key-callout hover. Lower alpha (0.25) and tighter
spread (6px/1px) than the violet glow — copper is accent, violet is primary.

### Allowed application sites for copper (5% rule — exhaustive)

| Element | Class | Screen(s) |
|---------|-------|-----------|
| Page eyebrow label ("Operator workspace") | `.ops-copper-eyebrow` | All 6 screens (replaces inline `text-secondary` utility) |
| Intent-card icon — key-callout / recommended | `.ops-copper-node` on `ops-intent-card__icon` | Control Room |
| Federation badge on search result rows | `.ops-badge.ops-copper-badge` | Search |
| Playbook workspace file-type badge | `.ops-badge.ops-copper-badge` | Playbooks |
| Key-node marker in any diagram/route context | `.ops-copper-node` or `.ops-copper-node--fill` | Future (Phase 133/134) |

**Forbidden copper targets:**
- Status indicators (error/warning/success/info) — these use semantic tone classes
- Primary navigation pills or active states — these use violet primary
- Large background areas or panel fills — copper is 5%, not dominant
- Body text, heading text, any extended prose

## Interaction Contract

### Glow on hover

The `.ops-glow` class adds `transition: box-shadow var(--duration-ops-fast) var(--ease-ops-standard)`
(120ms ease-out). On hover states that gain the glow, the transition runs at `--duration-ops-fast`
— consistent with existing hover feedback on `.ops-result-row`, `.ops-intent-card`.

### Copper badge — no hover glow

Copper badges (`.ops-copper-badge`) do NOT get the violet glow on hover. They may gain a
subtle copper glow (`--shadow-ops-glow-copper`) if used as a key-callout with a hover state,
but this is opt-in per site, not a default.

### Reduced motion

All new transitions (`--shadow-ops-glow`, `--shadow-ops-glow-copper`, badge transitions)
are covered by the existing global reduced-motion rule in `@layer base`:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition-duration: 0.01ms !important; animation-duration: 0.01ms !important; }
}
```

No new reduced-motion rules needed. Glow appears immediately (no transition) under
`prefers-reduced-motion: reduce` — acceptable, as it's a purely decorative affordance.
