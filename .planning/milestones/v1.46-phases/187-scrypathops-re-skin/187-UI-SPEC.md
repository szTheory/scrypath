# Phase 187 — UI Design Contract

> Visual and interaction contract for the ScrypathOps re-skin (plum/orchid identity, one sync-status vocabulary, light and dark). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Authority.** `187-CONTEXT.md` is locked and is not re-opened here. The brand book is the pinned copy in `brand/` (v1.0, `brand.json`, `tokens.json`, `BRAND.md`). Where the book is silent this file records a **local** default with a one-line reason and numbers computed from the palette (see Local Defaults Register). No default adds a hex that is not already a brand value, so the token allowlist does not grow.

**Tags.** `[L]` locked by CONTEXT. `[B]` from the brand book. `[local]` recommended default for a gap in the book. `[keep]` keep-platform: existing value, no reflow. `N-`, `E-`, `P-` ids point to the Assertion Index at the end; every rule here has one. There is no human UAT: a rule without an automated assertion is a defect in this file.

**Line numbers** are approximate (HEAD `267a5fa8`, 2026-11-19); re-derive on the working tree.

## Typography

Sizes are the platform scale plus the locked h1. This is 5 sizes and 3 weights, above the 3 to 4 and 2 guideline, on purpose: body reflow to the book's 16/28/13 is deferred to v1.48 `[L]`, and 700 exists only for the h1.

| Role | Size | Weight | Line height | Family | Used for |
|------|------|--------|-------------|--------|----------|
| Page title (h1, "Display" role in ops) | 28px | 700 | 1.2 | Hanken Grotesk, tracking -0.01em | `ops_page_header` only `[L][B]` |
| Section heading (h2) | 18px | 600 | 1.3 | Hanken Grotesk | `ops_heading` level 2, `ops_section`, modal title, verdict headline `[keep][local]` |
| Subheading (h3) | 16px | 600 | 1.3 | Hanken Grotesk; schema and index name headings Sometype Mono 500 | Row titles, record headings `[keep]` |
| Body | 14px | 400 (600 for buttons, actions, nav, table heads) | 1.5 | Hanken Grotesk | Paragraphs, values, form text `[keep]` |
| Label, meta, time | 12px | 400 (600 for `dt` labels and status words in dense counts; `kbd` is Sometype Mono 500) | 1.3 | Hanken Grotesk; times and identifiers Sometype Mono 400; `kbd` Sometype Mono 500 | `--text-ops-sm` role; letter-spacing 0.01em on 600 labels `[B]` |

Rules:

- **Floor `[L][B]`.** Every text-bearing element computes to at least 12px. `--text-ops-xs` (0.6875rem) is redefined to 0.75rem (alias of `--text-ops-sm`; no new size). The five sites at `.ops-text-meta`, `.ops-nav-group__label`, `.ops-signal-metrics dt`, `.ops-cmdk__item-hint` and `.ops-kbd` move to 12px (P-02).
- **No uppercase `[L][B]`.** `text-transform` never computes to `uppercase`; remove it at `.ops-copper-eyebrow` (≈786), `.ops-nav-group__label` (≈1149), `.ops-intent-card__flag` (≈1510), `.ops-signal-metrics dt` (≈1750), `ops_ui.ex` ≈401 (`ops_metric` label) and ≈516 (`ops_verdict` label). Labels are sentence case, 12px, 600, 0.01em, in `--ops-text-muted` (P-02, E-12).
- **Weight snapping `[L]`.** Hanken computes only 400, 600, 700; Sometype Mono only 400, 500. Snap table: 500 → 600 (`.ops-text-label`, `font-medium` ×3, `.ops-sync-work .ops-text-action`); 650 → 600 on Hanken and 500 on mono (`.ops-signal-metrics dd`, `.ops-kbd`, `.ops-metric__value`); 700 → 600 everywhere except h1. Nothing lighter than 400 (P-02).
- **Families.** `--font-sans: "Hanken Grotesk", "Hanken Grotesk Fallback", system-ui, sans-serif`; `--font-mono: "Sometype Mono", "Sometype Mono Fallback", ui-monospace, monospace`, both in `@theme`. Replace the four hard-coded `ui-monospace, "Cascadia Code", Menlo` stacks (≈968, 1110, 1759, 1973) with `var(--font-mono)`. `font-variant-ligatures: none` on `code, pre, kbd`.
- **Mono face `[L][B]`.** Computes to Sometype Mono: `.ops-time__value`, `[data-ops-timestamp-copy]`, `code`, `pre`, `kbd`, `.ops-inline-code`, and every element marked `data-ops-identity` (new marker on schema and index name headings such as `[data-testid="posture-row"] h3` and `.ops-failed-row__title > [title]`). CONTEXT's `[data-ops-copy]` is realized by `[data-ops-timestamp-copy]` plus `data-ops-identity`; the "Copy" button label keeps Hanken. `.ops-signal-metrics .ops-time` (≈2454) switches from `var(--font-sans)` to mono. `tabular-nums` stays declared; it is a no-op on Hanken digits and Sometype Mono has no slashed-zero feature, so none is declared.
- **h1 `[L]`.** `font-family` starts with `"Hanken Grotesk"`, 28px, 700. `--text-ops-h1` becomes 1.75rem (was 1.5rem); `ops_page_header` swaps `leading-ops-tight` (1.3) for a new `--leading-ops-title: 1.2` and `tracking-normal` for `-0.01em`. No element computes to Bricolage; `display.woff2` stays on disk (the pin verifier owns that directory) but is never declared or requested (E-14, P-02).
- **Size scale record `[L]`.** `--text-ops-sm`, `-body`, `-md`, `-lg`, `-h2`, `-h3` are recorded as `keep-platform` with their `value` in the token map where its parity scope covers `@theme` properties, otherwise in `DESIGN-TOKENS.md`; no body text reflows.
- **Glyph coverage `[L]`.** Read with fontTools from the shipped subsets on 2026-11-19. Both Hanken (`ui.woff2`) and Sometype Mono (`mono.woff2`) lack U+00B7 `·`, U+203A `›` and U+2318 `⌘`. Hanken also lacks U+2191 and U+2193 (the up and down arrows); the mono subset has them, which differs from the book's note. Hanken does contain U+2192 `→` and U+2190 `←`, plus `…` `—` `–` `’` `“` `”` `×` `•`, so text arrows are allowed. In ops the three missing glyphs render from the metric-adjusted fallback faces, then `system-ui` or `ui-monospace` (`·` 20 uses, `⌘` 5, `›` 3 in `lib/` and CSS). The coverage test (E-14) runs over rendered text only, not source files: the LiveView and HEEx output of the six screens plus CSS `content:` strings. Its named fallback allowlist is `·`, `›`, `⌘`. U+2500 `─` (519 uses) occurs only inside Elixir comments in `posture.ex` and `failed_sync_live.ex` (verified: no non-comment line contains it), so it is allowlisted as comment-only and a rendered `─` fails the test.
- **Font loading `[L]`.** CSS-relative URLs from `/assets/css/app.css`, so `../fonts/ui.woff2?v=<sha256>` resolves to `<mount>/assets/fonts/`; `font-display: swap`; no base64.

```css
@font-face { font-family: "Hanken Grotesk"; src: url("../fonts/ui.woff2?v=b9929d2465e7e4731ad39dcf88ab3e92b49f36685a2ec4add82f26ab6aa97a14") format("woff2"); font-weight: 400 700; font-style: normal; font-display: swap; }
@font-face { font-family: "Sometype Mono"; src: url("../fonts/mono.woff2?v=d8c5ea4cb7db8b0f56291ee28cf167a10406b36456856646edd58115c73530ea") format("woff2"); font-weight: 400 500; font-style: normal; font-display: swap; }
@font-face { font-family: "Hanken Grotesk Fallback"; src: local("Arial"); size-adjust: 101.7%; ascent-override: 98.3%; descent-override: 29.8%; line-gap-override: 0%; }
@font-face { font-family: "Sometype Mono Fallback"; src: local("Courier New"); size-adjust: 96.7%; ascent-override: 95.7%; descent-override: 28.5%; line-gap-override: 0%; }
```

Hashes are the sha256 of `scrypath_ops/priv/static/assets/fonts/ui.woff2` and `mono.woff2` as committed by Phase 186 (verified 2026-11-19); the contract test recomputes them rather than trusting this file (E-14). Preload `ui.woff2` with `crossorigin` only in the standalone root layout, never in mounted mode (E-15).

## Status Vocabulary `[L][B]`

### Component

```
ops_sync_status(status: :failed | :retrying | :pending | :clear)
<span class="ops-sync-status" data-sync-status="failed">
  <span class="ops-sync-status__word">Failed</span>
  <svg class="ops-sync-status__icon" data-shape="notched" aria-hidden="true" focusable="false" width="8.63" height="16" viewBox="0 0 8.63 16"><path d="…"/></svg>
</span>
```

- Word first, then the icon, `display: inline-flex; align-items: center; gap: 4px; white-space: nowrap`. Word weight 600, size inherits (≥ 12px), never uppercase. Word and icon color = `var(--ops-status-<status>)`; the icon uses `currentColor`. The icon is never rendered without its word and the word is never replaced by the icon. No `role`, no accessible name on the icon; the word is the accessible text. No transition, no animation (status-change animation is deferred).
- Word set is exactly `Failed`, `Retrying`, `Pending`, `Clear` (title case, one word each). The same word is never used for a different meaning (LD-9).
- Hooks that survive `[L]`: `data-status-kind` on `ops_status`, `data-ops-metric-tone` on `ops_metric`, `data-state` on `[data-testid="failed-sync-row"]`, `data-tone="error"` and `data-tone="retrying"` on the count wrappers in `.ops-signal-counts`, and all `data-testid` values named in this file. New: `data-sync-status` on the component and `data-shape` on its svg.

### Shapes (LD-7)

One sharp-cornered bar that leans 14.46° (4.13 over 16px), 16px tall, drawn in `viewBox="0 0 8.63 16"`. The shapes differ without color.

| Status | `data-shape` | Path `d` (fill `currentColor`, `fill-rule="evenodd"`) |
|--------|--------------|--------------------------------------------------------|
| Clear | `filled` | `M0 16H4.5L8.63 0H4.13Z` |
| Pending | `hollow` | `M0 16H4.5L8.63 0H4.13Z M1.61 14.75H3.53L7.02 1.25H5.10Z` |
| Retrying | `bottom-filled` | Pending path plus `M1.61 14.75H3.53L5.27 8H3.36Z` (the lower half of the hollow, filled) |
| Failed | `notched` | `M0 16H4.5L8.63 0H4.13L2.71 5.5L4.06 8L1.42 10.5Z` (a 2px bite out of the left edge at mid-height) |

Test: the four `d` values are distinct; each svg is 16px tall and `aria-hidden="true"` (E-01, P-03).

### Conditions (not statuses) `[L]`

`Not observed`, `Not checked`, `Queue not used`, `Unavailable` render as plain `--ops-text-muted` words, weight 400, no icon, no color, class `.ops-condition`. `Clear` appears only with an observation: the row is `{:ok, status}` with empty backend lists, and the queue is either observed-empty or not used by the sync mode (`:inline`, `:manual`). A zero count from an unobserved source never produces `Clear` (DESIGN.md "don't infer health from zero counts") (E-04).

### Row status and ranking `[L]`

Most urgent status of a Search health row, from the existing `status` map:

1. `failed`: `status.backend.failed` or `status.queue.failed` non-empty.
2. `retrying`: `status.queue.retrying` non-empty.
3. `pending`: `status.backend.pending` or `status.queue.pending` non-empty.
4. unverified: row is `{:error, _}` (condition `Not checked`), or the queue is unobserved and the mode uses a queue (condition `Not observed`).
5. `clear`: everything else.

Sort: rank 1 to 5 above, then module name (`inspect(mod)`); replaces `posture_row_rank/1` (≈528, which tied queue-failed with retrying and ranked pending as clean). Rows re-sort only on manual refresh (E-05). The Control Room verdict and the Search health summary verdict show the worst row status; `Clear` only if every row is `clear` (E-06).

### Where it renders

| Surface | Replaces | Rule |
|---------|----------|------|
| Failed sync work row | `ops_badge` with `state_label/1` (≈1034) | `:failed` or `:retrying` from `row.state` |
| Search health row header | the backend and queue `ops_badge` pair (≈345 to 356) | One status for the row (most urgent), or a condition word |
| Search health source groups | `<dt>` icon plus word (≈394 to 451) | `ops_sync_status` in `<dt>`; count stays in `<dd>`; a status with a zero list is not rendered |
| Control Room and Search health verdicts | `verdict_icon/1` | `status` attr |
| Sync and index activity list | `reconcile_signal_icon/1` (≈1713) | `:failed_sync_work` → `:failed`; `:pending_queue_work`, `:pending_backend_work` → `:pending`; other signals plain text |

Failed sync work and Sync and index never render `Clear` (they do not observe pending work).
