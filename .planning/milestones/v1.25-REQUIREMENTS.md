# Requirements: Scrypath

**Defined:** 2026-05-26
**Milestone:** v1.25 — *Tenant-Safe Search Access*
**Core Value:** Provide a first-class, built-in mechanism for multi-tenant SaaS applications to safely isolate search data, eliminating the "filter merge order" footgun that leads to silent data leaks.

## v1.25 Requirements

### Configuration and Metadata
- [ ] **AUTH-01**: `Scrypath.Searchable` exposes a declarative `tenant_field: :field_name` configuration block.
- [ ] **AUTH-02**: Declaring a `tenant_field` automatically appends that field to the index's `filterable:` array and ensures it is included in document projection.
- [ ] **AUTH-03**: The `schema_capabilities/1` reflection API surfaces `%{tenant_field: :field_name}` so that Plug pipelines or context layers can dynamically detect and enforce multi-tenancy requirements.

### Runtime Safety and Query Execution
- [ ] **EXEC-01**: The internal query compilation engine rewrites the filter merging logic to ensure tenant boundaries are immutable. A tenant filter MUST be combined with user-supplied filters using `AND` semantics, guaranteeing that `OR` clauses in user input cannot bypass the tenant restriction.
- [ ] **EXEC-02**: (Stretch) Introduce a `tenant_scope:` option on `Scrypath.search/3` that explicitly hard-injects the tenant boundary, preventing caller `filter:` opts from overriding it.
- [ ] **EXEC-03**: Introduce a `Scrypath.generate_tenant_token/3` helper for generating embedded, tenant-constrained JWTs for direct-to-engine frontend search integration.

### Documentation and Verification
- [ ] **DOC-01**: Publish a canonical `guides/multitenancy.md` guide that explains the "Shared Index + Tenant Tokens" architectural model, documenting how to secure searches at the Plug/Context layer and how to safely issue tenant tokens.
- [ ] **TEST-01**: Add hermetic tests to explicitly verify the filter compilation logic, ensuring complex nested `OR` conditions never escape the injected tenant scope.

## Future requirements carried forward

- [ ] **FACET-UX-01**: High-cardinality facet-value search (`search_facet_values/4`) — scheduled for v1.26.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Multi-index-per-tenant physical isolation | Physical index prefixing per tenant does not scale efficiently for high-density SaaS applications and drastically complicates index lifecycle management. The shared index model with strong filter enforcement is the target pattern. |
| Automatic Phoenix Plug assignment extraction | Scrypath remains framework-agnostic. Contexts or Plugs must explicitly pass the tenant scope into the library. |
