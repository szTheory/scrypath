# Milestone v1.22: Composition And Real-App Depth

**Status:** ✅ SHIPPED 2026-05-24
**Phases:** 83-85
**Total Plans:** 9

## Overview

`v1.22` turned the shipped request-edge toolkit into a bounded real-app composition layer. The milestone froze and implemented reusable preset/scope composition, declaration-backed metadata reflection, `search_many/2`-aligned lowering, and one canonical public guide that teaches the story without implying a second runtime, generated UI, or host-policy automation.

## Phases

### Phase 83: Composition Presets And Scope Contract

**Goal**: Apps can compose reusable single-search flows into the existing `Scrypath.search/3` input shape without creating a second query runtime.
**Depends on**: Nothing
**Plans**: 3 plans

Plans:

- [x] 83-01: Freeze the public plain-data composition contract and root boundary docs.
- [x] 83-02: Add the focused verification harness for precedence, visibility, and boundary drift.
- [x] 83-03: Implement normalization, merge/conflict logic, and make the focused phase gate pass.

**Details:**
Phase 83 established `Scrypath.Composition` as a public plain-data seam over the existing `Scrypath.search/3` vocabulary. It locked the fragment/result contract, added deterministic unit/property coverage, and implemented the merge engine with explicit fixed conflicts, stable visibility buckets, and a dedicated `mix verify.phase83` gate.

## Milestone Summary

**Decimal Phases:**

**Key Decisions:**

- Keep the new composition surface plain-data and function-first instead of exposing `%Scrypath.Query{}` or schema-generated runtime verbs.
- Keep metadata under `Scrypath.Metadata` as declaration-backed, framework-agnostic data for honest host rendering.
- Keep `compose_many/2` as a lowering helper over the existing `search_many/2` tuple/shared-option contract, with shared `fixed` intentionally unsupported.
