# Phase 188.1: CI path classifier - Research

**Researched:** 2026-11-20 (orchestrator read of `.github/workflows/ci.yml`, `test/mix/tasks/workflow_wiring_test.exs`, `reference/CI-EFFICIENCY.md`, PR #132). Primary evidence is the repo itself; no external sources are needed.

## Findings

- `ops-ui-path` (ci.yml ~line 357) is the pattern: classifier job with `outputs.run`, `fetch-depth: 0`, `push` to `main` always `run=true`, PR diff via `git diff --name-only origin/$GITHUB_BASE_REF...HEAD`. The dependent job uses `if: ${{ !cancelled() && (needs.X.result != 'success' || needs.X.outputs.run == 'true') }}`, so a failed classifier fails open.
- `ops-ui-path` is a denylist-style run trigger (runs on listed prefixes). The new classifier is the inverse: SKIP only when every changed path matches `^(\.planning/|docs/|[^/]+\.md$)`. Non-PR events (push, schedule, workflow_dispatch) must always run (`closeout-attestation` needs `ecommerce-mounted` on dispatch).
- Targets: `ecommerce-mounted (required)` (job-level `if`; skipped required context reports success) and the Node step in `repository-contracts (required)` ("Verify browser build, lifecycle, evidence, and target behavior" plus the "Install locked demo dependencies" npm step; step-level `if`, the job itself must still run because `mix verify.repository_contracts` stays). `repository-contracts` needs the classifier via `needs`.
- `docs/` is Hex-shipped (HexDocs guides) and `[^/]+\.md$` includes README/CHANGELOG; `package` and `core` still run on every PR, so docs contract tests (`package_metadata_test`) stay covered. Risk to check: any Node test or browser lane that reads `docs/` or root `*.md` (e.g. brandbook or README pin tests). Planner must grep `scripts/ci/*.test.cjs` and `examples/scrypath_ecommerce` for reads of `docs/`, `README.md`, `.planning/` and add those paths to the non-skippable set (shrinking the allowlist) if any exist.
- `workflow_wiring_test.exs` (1469 lines) pins job shapes: tests near lines 391 (path-dependent CI consumers), 554 (repository-contracts runs counted browser tests: keep the `# tests [1-9]` and `# fail 0` greps intact), 602-690 (CONTRIBUTING required-check contract and gate ledger, budget 12), 861 (mounted proof distinct and required). `upload-artifact` is pinned to the exact SHA `043fb46d...` # v7 at lines 1041, 1194, 1239 of the wiring test and in `.github/workflows/website.yml:59`; PR #132 bumps it to 7.0.2 in ci.yml and website.yml and fails `core` and `repository-contracts` only because of this exact-SHA assertion. Relax to a pattern (`actions/upload-artifact@<40 hex> # v7(\.\d+)*`) so the bump is accepted; keep the 40-hex SHA requirement (do not weaken to a tag).
- Measured before (CI-EFFICIENCY): a docs-only PR is about 19 minutes wall (ecommerce-mounted 1134 s) and about 35 runner-minutes.
- Open PRs: #132 (upload-artifact bump, BEHIND), #129 (`@axe-core/playwright` bump, BEHIND).

## Validation Architecture

- Cheap first: a pure classifier function testable without GitHub: put the regex in one place (a small script `scripts/ci/ecommerce_path_classifier.cjs` or an inline step the wiring test extracts). Unit tests: `.planning`-only diff skips; `docs/x.md` + `README.md` skip; one `lib/` path runs; mixed runs; empty diff runs; unknown/failed diff runs (fail open); non-PR events run.
- `mix test test/mix/tasks/workflow_wiring_test.exs` covers the wiring (job `if`, `needs`, fail-open expression, step-level `if` on the Node step, planted-diff test, pin pattern).
- `node --test` for the classifier test file; `mix format --check-formatted`; no new required gate (CONTRIBUTING ledger stays 8 of 12).
- Hosted proof at the exact head: this PR touches `.github/workflows/ci.yml`, so the classifier correctly runs everything on it (workflow file is not on the allowlist). The skip path is proved by the planted-diff tests, and measured on the next docs-only or planning-only PR (record honestly as "not yet measured on a hosted run" until then).
