       ```elixir
       defmodule Mix.Tasks.Scrypath.Settings.Read do
         @moduledoc """
         Prints current applied Meilisearch settings for one Scrypath schema.

         ## Usage

             mix scrypath.settings.read MyApp.Blog.Post
             mix scrypath.settings.read MyApp.Blog.Post --repo MyApp.Repo --index-prefix tenant

         Output is the raw Meilisearch settings map pretty-printed as Elixir. Useful
         for debugging or as input to `mix scrypath.settings.diff` investigations.

         ## Exit codes

           * `0` - settings read successfully
           * `1` - runtime error (index not found, network failure, bad schema arg)

         TUNE-08.
         """

         @shortdoc "Prints current applied Meilisearch settings for one Scrypath schema"

         use Mix.Task

         alias Scrypath.CLI.OperatorTask

         @impl true
         def run(args) do
           Mix.Task.run("app.start")

           {opts, argv} = OperatorTask.parse!(args)
           schema = OperatorTask.schema_from_argv!(argv)

           config = Scrypath.Config.resolve!(OperatorTask.runtime_opts(opts))
           index = resolve_index_name(schema, config)

           case Scrypath.Meilisearch.Client.get_settings(index, config) do
             {:ok, settings} ->
               Mix.shell().info(inspect(settings, pretty: true, limit: :infinity, printable_limit: :infinity))

             {:error, {:http_error, 404, _body}} ->
               OperatorTask.error!("scrypath.settings.read", :index_not_found)

             {:error, reason} ->
               OperatorTask.error!("scrypath.settings.read", reason)
           end
         end

         defp resolve_index_name(schema, config) do
           # Mirror the same idiom scrypath.status.ex uses. Grep scrypath.status.ex
           # to confirm whether it's backend.index_name/2 or a different helper, and use
           # the same one here. Do NOT invent a new helper.
           Scrypath.Meilisearch.index_name(schema, config)
         end
       end
       ```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-06-01 | Information Disclosure | `inspect/1` output to stdout | mitigate | Output is the raw Meilisearch applied-settings response. This does NOT include the Meilisearch API key, URL, or other auth material — `Client.get_settings/2` does not echo these into its response body. The task never stringifies `config`; only the `{:ok, settings}` payload from Meilisearch is printed. Assertion: `grep -n 'inspect(config\|inspect(opts' lib/mix/tasks/scrypath.settings.read.ex` must return zero matches. |
| T-19-06-02 | Tampering | unchecked argv | mitigate | `OperatorTask.parse!/2` and `OperatorTask.schema_from_argv!/1` validate switches and the schema argument before any wire call. Invalid input → `Mix.Error`. |
| T-19-06-03 | Denial of Service | large settings response + pretty-print | accept | `inspect/2 pretty: true, limit: :infinity` could produce very large output for pathologically large applied settings. Meilisearch applied settings are bounded in practice (< 100 KB). Operator acceptance. |
| T-19-06-04 | Information Disclosure | index-not-found error body | mitigate | `OperatorTask.error!("scrypath.settings.read", :index_not_found)` is called with the `:index_not_found` atom, not the raw error body. The raw body (which might include the API URL or other identifiers) is discarded at the pattern-match boundary. |

No high-severity threats. Read-only diagnostic task with no new surface.
