<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser keyboard/focus to `CommandPalette` hook | Untrusted keyboard events and focus movement are handled by existing client-side code. |
| Server-rendered flash to browser | Framework flash messages render visible alert UI and dismissal behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-135-07 | Spoofing | `#ops-cmdk`, `#ops-cheatsheet` ARIA state | mitigate | Keep `aria-modal` only with browser-proven bounded focus; otherwise downgrade semantics to match behavior. |
| T-135-08 | Tampering | `CommandPalette` hook | mitigate | Extend only the existing hook, preserve IDs/data attributes and close timer, and avoid a second hook or new dependency. |
| T-135-09 | Information Disclosure | Flash alert content | accept | Existing flash content is server-defined operator feedback; this phase changes chrome classes only and preserves passive semantics. |
| T-135-10 | Denial of Service | Overlay animation and shadows | mitigate | Use existing tokenized CSS under 300ms, no loops, no bounce, no focus steal, and no heavy visual effects. |
| T-135-SC | Tampering | npm/pip/cargo installs | mitigate | No install task exists; do not add command-palette or dialog dependencies. |
</threat_model>
