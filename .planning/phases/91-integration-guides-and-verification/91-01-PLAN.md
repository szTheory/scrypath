<!-- Sources verified on disk 2026-05-25. -->

Scrypath.sync_related/3 — lib/scrypath.ex (~line 186-195):
  Scrypath.sync_related(schema_module, records, opts)
  - opts[:fan_out] REQUIRED — raises ArgumentError if absent (lib/scrypath/sync.ex:42); names a key in the schema's fan_outs: declaration.
  - opts[:sync_mode] — :inline (resolve + sync_records now) | :oban (enqueue internal RelatedWorker).
  - inline returns {:ok, %{mode: :inline, status: :completed}}
  - oban returns   {:ok, %{mode: :oban, status: :accepted}}   ("durably queued", NOT "searchable now")

fan_outs: declaration on the OWNING schema (lib/scrypath/options.ex:806-857):
  use Scrypath, fields: [...], fan_outs: [
    <key>: [ target: <TargetSchema module>, resolver: {Mod, :fun, extra_args} ]
  ]
  resolver MFA invoked as apply(mod, fun, [first_arg | extra_args]).

RESOLVER-ARITY DUALITY (dominant correctness risk — the worked resolver in the guide MUST show this):
  - :inline path → resolver first arg = list of OWNING-SCHEMA RECORDS ([%Author{}])  (lib/scrypath/sync.ex:92)
  - :oban   path → resolver first arg = list of OWNING-SCHEMA DOCUMENT IDs ([author_id])  (lib/scrypath/sync/related_worker.ex:47)
  Both encoded by existing tests: related_test.exs:50 (records) vs related_worker_test.exs:60 (ids).
  The resolver MUST pattern-match both shapes and funnel to a reload-by-id query.

RelatedWorker.perform/1 outcome matrix (D-04 — lib/scrypath/sync/related_worker.ex:54-70, read-only):
  - :ok / {:ok, _}                                  → :ok
  - {:error, {:http_error, status, body}} 400..499  → {:cancel, "HTTP <status>: ..."}  (permanent, no retry)
  - {:error, reason} (5xx / generic)                → {:error, reason}                  (transient, Oban retries to max_attempts: 8)
  - invalid schema/fan_out                          → {:cancel, {:invalid_job, reason}} (permanent)
  Default max_attempts: 8 (related_worker.ex:5). There is NO public `use Scrypath.Oban.Worker` macro (D-03) — adopters never name the worker.
