<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser harness -> CI evidence summary | Retry and failure details cross from Playwright/test helpers into the workflow's promotion evidence record. |
| workflow runtime -> artifact store | Logs, reports, and health snapshots are uploaded for maintainer review and must stay bounded. |
| advisory lane -> future promotion review | Evidence emitted today may later justify or block branch-protection promotion. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-01 | Tampering | `.github/workflows/ci.yml` evidence summary | mitigate | Require run metadata, stable `job_name: phase105-e2e`, runtime, and explicit evidence files in a deterministic contract test before promotion evidence can be trusted. |
| T-111-02 | Repudiation | Playwright retry handling | mitigate | Emit `phase105-playwright.json` and classify pass-after-retry as `flaky_signal` rather than treating it as a clean pass. |
| T-111-03 | Information Disclosure | advisory failure artifacts | mitigate | Limit the upload to the Phoenix log, Playwright outputs, and bounded evidence manifests; exclude raw documents, broad dumps, secrets, and tokens from helper logging. |
| T-111-04 | Denial of Service | maintainer triage loop | mitigate | Generate failure classifications and a markdown summary so advisory failures can be routed without immediate reruns. |
| T-111-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install or dependency addition is part of this plan; supply-chain posture is unchanged. |
</threat_model>
