# Plan 02 — Async run lifecycle and catalog entry

<objective>
Refactor `PlaybookLive` so playbook execution uses `start_async` + `handle_async` with an explicit `run_ui` assign (`:idle | :running | :ok | :error`), monotonic `run_id`, wall-clock timeout via `Process.send_after`, `cancel_async` on cancel and on superseding catalog actions, and add catalog **`run_now`** event that validates JSON and invokes the **identical** async run entrypoint as preview **Run**.
</objective>

<threat_model>
**ASVS L1:** Double-submit and duplicate async results mitigated by `run_id` checks before applying async results (D-16). Timeout message must not leak internal PIDs. Cancel is best-effort; document in assigns only, not security boundary.
</threat_model>
