# Phase 134 — UI Design Contract

> Visual and interaction contract for SCREEN-DARK-01: bring v1.33's under-iterated surfaces
> (Search result rows, Sync/Drift drift-chips + preflight depth, Playbooks empty/populated)
> to dark-signature + light-parity quality across all seed states. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

> **This phase adds NO new design-system primitives, NO new tokens, NO new components, and NO
> new JS hooks.** It is a per-screen *application* pass that consumes the existing
> `scrypath_ops` design system established in phases 119–133. The single source for the
> findings this phase closes is `129-DARK-AUDIT-BACKLOG.md` rows **DK-11 → DK-18**. The token
> catalog is `scrypath_ops/assets/css/DESIGN-TOKENS.md` — that file is the authority; this spec
> only names which already-declared tokens each surface must consume and pins the small number
> of phase-specific value decisions (e.g. the dark hover-border alpha boost).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (established Phoenix/LiveView + Tailwind v4 + daisyUI design system — shadcn gate not applicable) |
| Preset | not applicable |
| Component library | daisyUI (unprefixed `btn/select/input/table/modal/checkbox`) + `.ops-*` Phoenix function components in `scrypath_ops/lib/scrypath_ops_web/components/ops_ui.ex` |
| Icon library | Heroicons (violet monoline; copper reserved per copper vocabulary) |
| Font | IBM Plex Mono (`.ops-text-mono`) for code/identifiers; Inter / Space Grotesk for body/heading per the live `@theme` stack (unchanged this phase) |

**Two governing laws (from DESIGN-TOKENS.md — must hold):**
1. daisyUI classnames stay **unprefixed**; custom classes are **`.ops-`** BEM-ish. Never mix namespaces for one concept.
2. Never hardcode a raw Tailwind step (`p-4`, `text-2xl`, `rounded-md`, `shadow-sm`, raw `color-mix(...base-content NN%...)`) when an `-ops-` token / named floor exists.

**Both-themes invariant (hard):** every dark change is authored in **BOTH** the `[data-theme="dark"]`
selector path **and** the `@media (prefers-color-scheme: dark) html:not([data-theme="light"])` path
(system-dark parity, D-08). **Light must stay pixel-identical** — verified by the light pixel-diff +
light contrast gate after the change. Any light regression fails the phase.

## Spacing Scale

Declared values (the existing `--spacing-ops-*` scale; multiples of 4 honored via rem steps). This phase reuses it; it declares no new spacing.

| Token | Value | Usage |
|-------|-------|-------|
| `--spacing-ops-1` | 4px (0.25rem) | Icon gaps, inline padding |
| `--spacing-ops-2` | 8px (0.5rem) | Compact element spacing (`space-y-ops-2` stacked code blocks) |
| `--spacing-ops-3` | 12px (0.75rem) | Result-row / data-card interior padding (`p-ops-3`) |
| `--spacing-ops-4` | 16px (1rem) | Default element / row spacing |
| `--spacing-ops-row` | 16px (1rem) | Between list items |
| `--spacing-ops-panel` | 20px (1.25rem) | Panel interior padding (`p-ops-panel`) |
| `--spacing-ops-section` / `--spacing-ops-page-gap` | 24px (1.5rem) | Between major page sections / top-level page gap |

Exceptions: none. **Do not add `mt-*` to `:ops` shell page children** — the shell wraps content in `space-y-4`; lean on the container gap (page-rhythm rule).

## Color

Dark is the signature theme; light is at parity. The brand ratio target is **65/20/10/5**
(neutral / surface-step / violet primary / copper accent). Values below are the live `@theme`
tokens — **unchanged this phase** (no v1.35 brand-token refinement shipped). This phase's job is
to make the *existing* tokens land correctly on the three target surfaces.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (~65%) page floor | `--ops-bg` `#faf7f2` | `--ops-bg` `#0c0f14` | App background / shell floor |
| Surface-1 (resting panel) | `--ops-surface-1` `#fffdf8` | `--ops-surface-1` `#141923` | `.ops-panel`, `.ops-preflight__card`, `.ops-surface-flat` |
| Surface-2 (raised / muted step ~20%) | `--ops-surface-2` `#faf7f2` | `--ops-surface-2` `#1b2230` | `.ops-result-row`, `.ops-data-card`, `.ops-muted-panel`, `.ops-disclosure`, `.ops-verdict-neutral`, `.ops-preflight__card--locked` |
| Border / divider | `base-300` `#ded8ce` | `base-300` `#2a3446` | 1px borders, table row separators (blue-gray slate in dark) |
| Primary / violet (~10%) | `primary` `#5b4ad1` | `primary` `#6c5ce7` | Active nav, primary CTA, route mark, **hover border + violet glow** on interactive rows / active path nodes |
| Accent / copper (~5%) | `secondary` `#a85d2e` | `secondary` `#c17a3e` | Copper accent vocabulary only (eyebrow, key-callout badge, key-node) |
| Destructive | `error` `#d96262` | `error` `#d96262` | Playbook **Delete** action only — never decorative |

**Accent reserved for (exhaustive — never "all interactive elements"):**
- **Violet glow** (`--shadow-ops-glow`, dark-only / `none` in light): the route mark, active nav, the **recommended** Control Room intent card (`.ops-intent-card--recommended`), and the **active Playbook item** (`.ops-object-item-active`). **Never** on text, resting panels, ordinary buttons, broad backgrounds, or status surfaces.
- **Violet hover border**: interactive Search result rows and object items on `:hover` only.
- **Copper** (`.ops-copper-eyebrow`, `.ops-copper-badge`, `.ops-copper-node[--fill]`): page eyebrow labels, intent-card / playbook-file / key-callout badges, and key-node emphasis. Copper is **NEVER a status tone** — it does not appear in `tone_class/1` / `badge_class/1`. Apply at ~5% so the surface reads "earned, on the scan path" not decorative (success criterion 3).

**AA hard gate (inherited from Phase 132 — must stay green in light, dark, AND system-dark):**
no color/alpha decision in this phase may introduce an AA color-contrast failure. The
copper-on-surface and dark-text-on-copper AA pairings are pre-cleared in DESIGN-TOKENS.md
(eyebrow ≥4.84:1, badge text ≥12:1). Re-run `make contrast` + `npm run test:e2e:admin-contrast`
after the change; any new AA failure fails the phase.

## Per-Surface Visual Contract (the load-bearing section)

Each row below closes a `129-DARK-AUDIT-BACKLOG.md` finding. "Reuse token" = already declared; do not invent new ones.

### Search — result rows (DK-17, success criterion 1)

- Resting fill: dark `--ops-surface-2` `#1b2230` (already wired at `app.css:1434-1441`, both dark paths) so rows lift off the `#0c0f14` floor and **visibly separate** in dark. Light keeps `base-100 94%` fill.
- Border at rest: `color-mix(base-content 10%)` (existing). In dark this reads against surface-2, not the floor.
- **Hover (the phase-specific decision):** keep `box-shadow: var(--shadow-ops-mid)` (existing). Boost the dark hover border from the shared `primary 32%` to **`primary 55%`** so hover is perceptible against the lifted surface-2 (DK-17). Author the boost dark-only in BOTH dark paths; light hover border stays `primary 32%` (pixel-identical). Do not change the resting border.
- Press: existing `transform: scale(0.995)` at `--duration-ops-instant` (A4 parity — unchanged).
- Row content unchanged: single-index rows still lead with the human field name (`hit_title/2`, P29) — this is a visual/depth pass, not a content change.

### Sync/Drift — drift-chips + preflight depth (DK-16, success criterion 2)

- Section panels (`.ops-muted-panel`: "read-only checks", promotion preflight, index contract) consume `--ops-surface-2` so the section headers sit a clear elevation step above shell floor in dark — distinct sections, not coplanar.
- Preflight cards: `.ops-preflight__card` = `--ops-surface-1`; locked variant `.ops-preflight__card--locked` = `--ops-surface-2` (the step *up* communicates locked/raised). Verify the 4-step preflight reads with depth at `:wide` width (B6, already wired Phase 125) in both themes.
- Drift-chips: alternating `:success` / `:warning` / `:neutral` tone chips via `tone_class/1` — unchanged semantics. Verify chip contrast against the now-lifted surface-2 panel in dark (AA gate). Counts stay `:neutral` ("don't cry wolf"); only real problems are `:warning`/`:error`.
- Optional earned copper: a key-callout badge in preflight may use `.ops-copper-badge` if it serves the scan path — not required, not decorative.

### Playbooks — empty + populated (DK-18, success criterion 2)

- Workspace file data-cards (`.ops-data-card`, empty-result / federated / single-index) consume `--ops-surface-2` in dark (wired `app.css:1424-1431`) so the three cards read as **distinctly raised** surfaces in both empty and populated states, all seed scenarios.
- Active Playbook item: `.ops-object-item-active` carries the inset violet ring + `--shadow-ops-glow` in dark (Phase 133, `app.css:1495-1502`) — patch-safe server-state class. Verify it reads as the active path node and does not re-fire on LiveView patch (A3 precedent).
- Empty state uses the shared `ops_empty_state` naming the next action (P29, sentence case) — preserve the existing copy contract below.
- Destructive **Delete** stays in its own `ops_action_group tone={:danger}` (P28) — split from non-destructive actions.

### Cross-screen depth (DK-11, DK-13, DK-14, DK-15 — verify-and-tune, mostly inherited)

- DK-11 Control Room verdict panel / DK-15 Failed Sync triage notice: confirm the systemic ramp (`.ops-verdict-neutral` / `.ops-notice-surface` → surface-2) makes them read as raised above the shell in dark. No new fix expected if the systemic token propagates; tune only if a target shot still shows coplanarity.
- DK-13 Posture table row separators: if rows still read faint at dark mobile 390px after the ramp, boost the dark-only row-border alpha from `base-content 12%` toward **`18%`** (blue-gray slate per brand §6.5) — dark-only, both paths, light unchanged.
- DK-14 Posture verdict hero: confirm `.ops-verdict--hero` reads as the most-elevated element in dark via the `--shadow-ops-panel-dark` ambient recipe; layer it under the existing cream `shadow-ops-raised` only if the warm shadow still reads as a halo.
- DK-12 Control Room intent-card copper: apply `.ops-copper-badge` / `.ops-copper-node` to the recommended intent-card's federation badge or key-callout so the card reads as "Scrypath brand" not generic ops — at ~5%, earned.

## Copywriting Contract

Copy is established (Phase 124 IA-01/COPY-01: sentence-case titles, concrete-next-action states). This phase **preserves** it; it is a visual/depth pass. Listed for the checker's contract completeness.

| Element | Copy |
|---------|------|

| Primary CTA (Playbooks) | "Capture playbook" (capture title input + save) |
| Empty state heading (Search zero-results) | "No hits for this probe" |
| Empty state body (Search) | "Adjust the query or schema, then run another probe." (names the next action) |
| Empty state heading (Playbooks) | "No saved playbooks yet" |
| Empty state body (Playbooks) | "Capture a probe from Search to start a playbook." (threads the Search→Playbooks explore loop) |
| Error state (Search/Drift) | "{problem, e.g. 'Search backend unreachable'} — {next step, e.g. 'check the index status on Posture, then retry'}." |

Sentence-case throughout. Neutral facts (counts) read as `:neutral`, never `:warning` (don't cry wolf).
