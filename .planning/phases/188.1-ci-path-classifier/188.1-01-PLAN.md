Facts already established while planning (2026-11-20, re-verify cheaply, do not re-research):

- `ops-ui-path` (ci.yml) is the pattern: `fetch-depth: 0` checkout, `outputs: {run: "${{ steps.check.outputs.run }}"}`, dependent job `if: ${{ !cancelled() && (needs.ops-ui-path.result != 'success' || needs.ops-ui-path.outputs.run == 'true') }}`. Note its `git diff | grep -q` pipeline turns a failed diff into run=false, so it skips `ops-ui` when its diff command errors. The new classifier must NOT copy that shape: it computes the diff in a script and any failure yields run=true.
- A job with `needs: X` is SKIPPED when X fails unless its own `if` contains a status function. `repository-contracts` is a required context and must keep running its contract suite, so it needs a job-level `if: ${{ !cancelled() }}` plus step-level gating on the two Node steps.
- `git diff --name-only` collapses a rename to its new path only. A rename from `lib/x.ex` to `docs/x.md` would look docs-only. Use `--no-renames` and `-z`.
- Filenames are attacker-controlled input in a PR. Never write a path or an error message into `$GITHUB_OUTPUT` (a newline in a filename could inject `run=false`). Outputs carry only `run=` and a fixed-vocabulary `reason=`.
- Readers of allowlisted paths (grep run 2026-11-20 over `scripts/ci/ecommerce_*.cjs`, `scripts/ci/ui_state_pairs*.cjs`, `dev/mix/tasks/verify/ecommerce_mounted.ex`, `examples/scrypath_ecommerce/e2e/`): the only hits are two COMMENTS in `e2e/ops_host_contract.spec.ts` that mention "the README". `ecommerce_build.test.cjs` only asserts `.planning` is in `.dockerignore`. `ui-tokens.test.mjs` (retired-identity scan over docs/ and root `*.md`) runs inside ExUnit in `core` and `repository-contracts`'s mix step, which are never skipped. Result: the allowlist is NOT shrunk. If Task 1's re-run of that grep shows a real reader, shrink the allowlist (and update the CI-01 wording in REQUIREMENTS.md to match) rather than keep a path that a lane reads.
- `workflow_wiring_test.exs` already runs node tests from ExUnit via `System.cmd` (test "Node BEAM cache and exact-source collector boundaries execute inside the wiring contract lane"), so the classifier's node test can run in the always-on `core` and `repository-contracts` mix steps; it does NOT need to join the (skippable) browser Node step.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR contents to classifier | Changed file paths are attacker-controlled strings (a contributor or a compromised dependency PR chooses them) and decide which required lanes run |
| classifier to `$GITHUB_OUTPUT` | A step output is parsed line by line by the runner; text written there can set or override other outputs |
| classifier job to required jobs | A failed, timed-out or cancelled classifier changes the result that `needs` consumers see; a skipped required job reports success |
| PR workflow edits to the classifier | The PR can modify `ci.yml` and `scripts/ci/` themselves |
