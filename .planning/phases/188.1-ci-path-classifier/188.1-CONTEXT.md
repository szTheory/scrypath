<decisions>
## Implementation Decisions

- The `ecommerce-path` classifier mirrors the existing `ops-ui-path` pattern (classifier job plus a job-level `if`), so a skipped required context still reports success.
- The classifier is an ALLOWLIST: browser lanes are skipped only when every changed path matches `^(\.planning/|docs/|[^/]+\.md$)`. Anything else, an empty diff, a diff it cannot compute, or any error fails open to running the lanes.
- It skips `ecommerce-mounted` and the Node step of `repository-contracts` (the rest of `repository-contracts` and `core`, `package`, `backend` keep running).
- `workflow_wiring_test` gains: a planted diff touching one non-allowlisted path that the classifier would skip must fail, and a `.planning`-only diff must be accepted. It also pins `upload-artifact` by pattern, not a fixed SHA.
- Record the change in `.planning/reference/CI-EFFICIENCY.md` (finding 2 outcome, measured before: 19 min wall, about 35 runner-minutes; after: measure on this PR's own docs-only follow-up or the next planning-only PR, state honestly if not yet measured).
- After merge: `gh pr update-branch 132`, merge #132 on green; re-run #129 on the re-skinned base, merge if green, otherwise leave open and record the real cause.
- PR title `chore(ci): ...`; squash-merge on green required checks on the exact head. No change to branch protection, no new required check.
