<objective>
Add **`mix scrypath.settings.hot_apply`** as a thin operator entrypoint (D-08): shared runtime switches, **`--ack-live`** acknowledgement, **`--settings-file PATH`** (JSON object) supplying the hot map, delegate to **`Scrypath.Meilisearch.Settings.hot_apply/3`**, human-readable stdout, and **`Mix.raise` / `Mix.Error`** for operator mistakes (missing ack, missing file, bad JSON, API validation errors) consistent with **`scrypath.settings.read`**. Register **`preferred_envs`** in **`mix.exs`**. Add **Mix task tests** and an **`@moduletag :integration`** file that exercises happy-path hot apply on a disposable index (reuse **`QueryablePost`** + **`MeilisearchIntegration`** patterns from `search_many_integration_test.exs`).
</objective>

<threat_model>
**ASVS L1 — operator CLI**

| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-25-CLI: Shell history leaks settings JSON | Low | Document that operators should prefer **`--settings-file`** with `600` perms if JSON contains sensitive terms; do not print full JSON back on success |
| T-25-CLI: `--ack-live` bypass confuses users | Low | Moduledoc states live mutation; require flag on every invocation |

No elevation of privilege; uses existing config resolution.
</threat_model>
