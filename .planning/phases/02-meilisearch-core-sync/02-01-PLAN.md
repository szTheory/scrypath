<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application records -> shared sync orchestration | Caller-owned structs and maps cross into Scrypath write orchestration. |
| schema metadata -> delete execution | Configured id fields and custom identity hooks influence which backend document ids are deleted. |
| runtime options -> backend dispatch | Call-site options select backend and execution mode. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | delete identity resolution | high | mitigate | Keep delete identity on a dedicated `Scrypath.Identity` path backed by metadata or `search_document_id/1`, and cover it with tests proving delete does not use projection output or row reloads. |
| T-02-02 | Repudiation | public sync surface | medium | mitigate | Expose explicit lifecycle verbs under `Scrypath.*` and verify them through public-API tests so insert/update/delete semantics are obvious from the contract. |
| T-02-03 | Denial of Service | batch orchestration | medium | mitigate | Reuse one list-oriented orchestration layer for single and batch operations so validation and backend dispatch do not drift into inconsistent code paths. |
</threat_model>
