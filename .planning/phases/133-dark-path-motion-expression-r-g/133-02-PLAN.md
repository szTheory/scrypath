  <action>
    Create `ScrypathOpsWeb.MotionContractTest` mirroring `design_tokens_contract_test.exs`'s structure
    (`use ExUnit.Case, async: true`; `@app_css` path-expanded to `assets/css/app.css`; a `css/0` helper
    doing `File.read!`). Isolate the new rule blocks by extracting every CSS rule whose selector contains
    `ops-path` or `ops-code-block--shimmer` (regex over the declaration block between `{` and `}`), then
    encode three assertions:

    1. Transform/opacity-only: assert NO extracted block declares an animatable layout/visual property
       outside the allowed set — fail if any block contains `width:`/`height:`/`top:`/`left:`/`margin`/
       `filter:`/`background-position`/`stroke-dashoffset` inside a `transition`/`animation` or as an
       animated end state. Allowed animated properties: `transform`, `opacity`, `box-shadow`.
    2. Tokenized duration <300ms: assert every `transition:`/`animation:` declaration in an extracted
       block references a `--duration-ops-*` token (regex `var\(--duration-ops-`) and contains NO raw
       `\d+ms`/`\d+s` literal. (The tokens are all ≤240ms by definition, so token-use proves <300ms.)
    3. Dual-dark-path: for any selector that sets a dark-only glow/color end state under
       `[data-theme="dark"]`, assert a matching selector exists under
       `@media (prefers-color-scheme: dark)` / `html:not([data-theme="light"])`. Implement as: collect
       `.ops-path-*` selectors appearing after a `[data-theme="dark"]` context and assert each also appears
       in the system-dark media context (or assert symmetry of the two dark-branch selector sets for
       `ops-path`). If Plan 01 added zero dark-only path glow (e.g. glow rides an existing dual-pathed
       rule), this assertion may be a no-op pass — document that with an inline comment.

    Use exact-literal allowlist markers ONLY if a forbidden token must appear in the test as a search
    needle (the needles like `stroke-dashoffset` live in the test's own assertion regex, not in app.css,
    so no comment-text-discipline conflict arises in app.css). Keep the test deterministic and fast
    (pure file read + regex, no DB, `async: true`).
  </action>
  <verify>
