<objective>

Add **documented, code-floored** playground bounds under **`:scrypath_ops`** plus a **`ScrypathOps.SearchPlayground`** module (validation + **`Scrypath`** adapter indirection) so **`SearchLive`** can clamp/validate **before** calling the library and tests can swap the adapter without Mox.

</objective>

<threat_model>

| ID | Threat | Severity | Mitigation in this plan |
|----|--------|----------|-------------------------|
| T-46-01 | Missing config implies unbounded `page.size` / schema breadth in prod | high | Code defaults (**15** page size, **50** max page aligned with **`@max_page_size`**, **10** max schemas aligned with **`MultiSearch.Entries`**) always apply; host may only **lower** max schemas or tighten max page within **[1, 50]** — document in README. |
| T-46-01b | Adapter indirection calls arbitrary code in prod | medium | Default adapter is the only production path unless an operator explicitly sets **`:search_playground_adapter`** in **their** `runtime.exs`; README warns this is test/stub only. |

</threat_model>

<action>

1. Add **`lib/scrypath_ops/search_playground.ex`** (or split submodules if you prefer) implementing at minimum:
   - **`default_page_size/0`** — returns **`15`** unless **`:search_playground_default_page_size`** is set.
   - **`max_page_size_allowed/0`** — returns **`min(configured_max || 50, 50)`** and **`max(configured, 1)`** so the effective range is always **`[1, 50]`** (library ceiling).
   - **`max_schemas_allowed/0`** — returns **`min(configured || 10, 10)`** (library default cap); host may set **`:search_playground_max_schemas`** to an integer **`1..10`** only — if invalid at runtime, **ignore and use 10** *or* document clamp behavior in README (pick one, stay consistent in tests).
   - **`validate_page_size!/1`** or **`validate_page_size/1`** — if integer **> `max_page_size_allowed/0`** or **< 1**, return **`{:error, {:page_size_out_of_range, n, max}}`** (exact tuple atoms as written) **without** calling **`Scrypath`**.

2. Add **`lib/scrypath_ops/search_playground/adapter.ex`** defining a **`@behaviour`** with **`search/3`** and **`search_many/2`** matching **`Scrypath`** return types, plus **`ScrypathOps.SearchPlayground.Adapter.Scrypath`** default implementation that delegates to **`Scrypath.search/3`** and **`Scrypath.search_many/2`**.

3. Add **`adapter/0`** reading **`Application.get_env(:scrypath_ops, :search_playground_adapter, ScrypathOps.SearchPlayground.Adapter.Scrypath)`** and **`dispatch_search/3`**, **`dispatch_search_many/2`** that delegate to **`adapter().search(...)`** / **`search_many(...)`**.

4. Wire **defaults** in **`scrypath_ops/config/config.exs`** for the new keys (use the exact atom names you implemented). Optionally extend **`runtime.exs`** with env vars (executor-chosen names) documented in README — follow the spirit of **`SCRYPATH_OPS_SCHEMAS`**.

5. Document every new **`:scrypath_ops`** key and env var in **`scrypath_ops/README.md`** in a subsection titled **`Search playground bounds`** (exact heading substring).

</action>
