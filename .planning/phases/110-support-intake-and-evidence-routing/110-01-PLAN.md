<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adopter-facing docs -> support policy | README, CONTRIBUTING, and public route pages can accidentally become competing compatibility authorities. |
| public issue template -> maintainer triage | Outside-adopter evidence enters through a public template where missing fields or unsafe log guidance can derail classification. |
| operator/public entrypoints -> intake workflow | Route-only pages can blur whether the next step is readiness verification, maintainer intake, or unsupported ad hoc support. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-110-01 | Tampering | README, CONTRIBUTING, website/docs route copy | mitigate | Keep `guides/support-and-compatibility.md` as the single authority and remove any new tuple duplication or second-source support policy. |
| T-110-02 | Repudiation | `guides/outside-adopter-intake.md` routing taxonomy | mitigate | Add one explicit Class A-D x finding-bucket routing table/checklist so maintainers do not invent labels or actions ad hoc. |
| T-110-03 | Information Disclosure | `.github/ISSUE_TEMPLATE/outside-adopter-evidence.md` | mitigate | Add a compact required Evidence Block plus a redaction warning for secrets, tokens, API keys, and sensitive dumps before public submission. |
| T-110-04 | Tampering | `docs/operator-support.md`, `website/src/pages/docs.html`, `website/src/pages/operators.html` | mitigate | Restrict these surfaces to route-only support/intake wording and forbid compatibility tuple matrices or full policy duplication. |
| T-110-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are part of this plan; supply-chain posture is unchanged. |
</threat_model>
