<objective>

Deliver an **explicit, test-backed security model** for OPSUI: **fail-closed** behavior in **`prod`** unless **`OPSUI_AUTH_MODE`** is set to a **documented** allowed value; permissive **dev** documented; **`SECURITY.md`** covering WebSocket origin, cookies, CSRF, TLS, reverse-proxy vs in-app auth; **low-cardinality telemetry** rules cross-referencing `docs/search-backend-sre.md`.

</objective>

<threat_model>

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-44-04 | Operator UI exposed in prod with open defaults | **high** | **`Application.start/2`** refuses to boot in **prod** when `:validate_opsui_auth_on_start` is true and `OPSUI_AUTH_MODE` is missing or not in `["basic","proxy_headers"]` (extendable list documented for future OIDC). |
| T-44-04b | Telemetry leaks query text or IDs | medium | Document forbidden metadata keys/patterns; shell only emits coarse labels. |
| T-44-04c | WebSocket cross-origin attacks | medium | Document `check_origin` and reverse-proxy TLS termination expectations. |

</threat_model>
