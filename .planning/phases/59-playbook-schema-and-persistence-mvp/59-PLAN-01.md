# Plan 01 — Playbook v1 codec, strict validation, and tests

<objective>
Implement **OPS-PB-01** per **59-CONTEXT.md**: add **`ScrypathOps.Playbook.V1`** with **`decode/1`** (binary or UTF-8 string → string-keyed map via **`Jason.decode/2`** without **`keys: :atoms!`**), **`validate/1`**, and **`encode/1`** (normalized map suitable for **`Jason.encode!/1`**). Enforce **`playbook_format: 1`**, **`mode`** **`"search"`** / **`"search_many"`**, strict unknown keys, **`SearchPlayground.validate_page_size/1`** on nested **`page.size`**, entry count **`≤ SearchPlayground.max_schemas_allowed/0`**, and reject banned transport/secret keys (**`meilisearch_api_key`**, **`req_options`**, **`meilisearch_url`**, **`meilisearch_client`** — for v1 **reject `meilisearch_client` in JSON playbooks**). Add **ExUnit** coverage without live Meilisearch (roadmap success criterion 3).
</objective>

<threat_model>
| ID | Threat | Severity | Control |
|----|--------|----------|---------|
| TM-59-01 | Atom exhaustion / unsafe atom creation from JSON | High | String-keyed decode; atomize only whitelisted keys after validation |
| TM-59-02 | Secrets exfiltration via playbook files | High | Reject banned keys per **59-CONTEXT D-04**; no `req_options` / API keys in v1 payload |
| TM-59-03 | LFI via path fields in future import | Medium | Phase 59 codec does not `Path.expand` user paths; document **D-05** in moduledoc |

**ASVS-style scope:** operator-supplied JSON at rest; treat as untrusted input.
</threat_model>
