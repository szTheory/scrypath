<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime → Meilisearch JSON | `facet_filter` values flow into HTTP body — must use same encoding rules as `filter` (no raw string concatenation of user blobs without JSON encoding). |
| backend → decoder | Malicious Meilisearch could return odd shapes; decoder must not crash the VM on non-map distribution entries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-02-01 | Injection | `facetFilters` string building | mitigate | Reuse `format_value/1` / `translate_filter` patterns from `Meilisearch.Query`; never interpolate unescaped binary. |
| T-20-02-02 | Denial of Service | decoder on huge facet maps | mitigate | Decoder runs only on backend response inside `decorate_result`; rely on Meilisearch max_values_per_facet + tests for reasonable map sizes; document no unbounded recursion. |

No high-severity threats identified for library-local facet encoding beyond existing search filter path.
</threat_model>
