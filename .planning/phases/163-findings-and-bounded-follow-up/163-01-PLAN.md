Existing check_baseline.py resolves ROOT with Path(__file__).resolve().parents[3], reads its fixed Markdown sibling, checks an exact 19-column header, and emits PASS: N claim rows checked. Keep that implementation and grammar intact.

New phase-local contract: check_findings.py accepts --claims as a comma-separated exact C-ID subset and --stage triage|dispositions|complete, with complete as default. With no --claims, derive expected IDs from the canonical baseline; do not assume numeric order, ignore new suffixed IDs, or use a fixed count. The normal no-argument command requires full inventory and complete candidate/proof decisions. Subset or earlier-stage success must print PARTIAL and the actual checked IDs/stage. Complete success prints PASS: findings structural contract; claims=N; material=N; candidates=N; proofs=N. Exit nonzero with ID — field: reason on invalid input, a missing/duplicate/unknown ID, unresolved local link, or contract violation. Standard library only; never execute command strings or fetch links while validating.

Document layout: one ## Claim triage table with exact columns Claim | Job | Classification | Evidence and limits | Decision relevance | Finding | Qualification. Claim cells include the stable C-ID and baseline Markdown link; each row may link multiple finding cards. Classifications are no-new-observation, evidence-gap, observation, product-opportunity, material-defect, material-risk; use the dominant material class when a claim has several observations and describe each separately. Nonmaterial rows have no rank. Qualification is not-qualifying with a reason, review-required during staged execution, or links to K-NN cards. Final mode rejects review-required.

Use ### F-NN cards under ## Material findings, ### K-NN cards under ## Follow-up candidates, and #### P-NN cards nested under their selected F/K owner. Card fields are one-line "- Name: value" entries with continuation prose allowed outside the field value. All IDs unique; validate both directions of C-to-F, F-to-K, and parent-to-P references. Empty findings/candidates sections explicitly state None with a linked inventory rationale; an empty baseline or triage table is an error.

F fields: Claims, Job, Scrypath boundary, Evidence, Impact, Frequency/exposure, Confidence, Compatibility risk, Security risk, Privacy risk, Data-integrity risk, Operational risk, Implementation cost, Regression cost, Recurring verification cost, Rank, Rank rationale, Disposition, Disposition basis, Risk state, Owner, Decision evidence, Revisit trigger, Route. Rank is Critical/High/Medium-leverage/Low; disposition is closed/accepted/deferred/rejected. Risk state is resolved/accepted/unresolved/not-substantiated, independently recorded so a rejected remedy cannot conceal an unresolved risk. Missing applicable facts use reason-bearing unknown, not invented facts. Evidence/rank fields are required even at triage stage for an actual F card; dispositions stage enforces its treatment and complete stage also enforces its qualification route. Closed requires a claim-specific proof link and resolved risk; accepted requires a real owner and decision-source link and accepted risk; deferred requires a named accountable role/person plus event trigger and unresolved risk; rejected must state whether the asserted finding or only the proposed remedy is rejected, using not-substantiated or unresolved accordingly.

K fields: Name, Findings, Outcome, Evidence, Owner boundary, Scope authority, Exclusions, Route, Route rationale, Work units, Value/cost rationale, Acceptance claims. Route is milestone or focused-patch. Work units name the bounded coordinated tasks and necessary order that justify the selected route. Referenced findings must exist and be material; unresolved evidence observations are not candidate findings. A missing scope authorization leaves the item nonqualifying with its missing condition visible.

P fields: User outcome, Boundary, Exclusions, Fixture, Oracle, Layer, Command, Environment/versions, Receipt, Invalidation trigger, Timeout, Diagnostics, Isolation, Cleanup, CI posture, CI economics. Layer is unit/property, contract/seam, integration, package/service, browser, or exact-SHA-hosted. Receipt is an actual linked result with SHA/environment when relevant, or explicit "not executed — proposed follow-up acceptance" with reason. Unsupported infrastructure is a named follow-up prerequisite, never described as runnable today. Fields inapplicable to a pure proof include a reason. Changed CI posture needs a comparison of incremental confidence, recurrence, runtime, maintenance, reliability, isolation, and diagnostics; unchanged posture needs only claim-local rationale. No phase-wide proof manifest or CI catalogue.

Global checks apply only without --claims. At dispositions stage require ## Disposition summary fields Claims, Material findings, Closed, Accepted, Deferred, Rejected, and Unresolved gate-rank findings; derive counts and F-ID lists from cards. At complete stage additionally require Candidates, Proof claims, and ## Phase 164 handoff with linked baseline, dispositions, residual gaps, candidate/nonqualification outcome, unresolved owner decisions, and explicit Phase 164 gate ownership. An unresolved gate-rank list includes all Critical/High/Medium-leverage cards with Risk state unresolved; reject disposition/risk-state contradictions. These are structural checks of declared data, not verification that owner authority is genuine. Partial validation checks every selected record and connected card fully for its stage, but cannot claim global summary/handoff completion.
