<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw search hits -> hydration layer | External search results influence which source rows Scrypath loads from the repo. |
| repo-backed hydration -> caller result | Hydrated records and missing rows become part of the public result contract. |
| preload options -> hydration query | Caller-controlled preload behavior affects only repo-side hydration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Information Disclosure | hydration query | medium | mitigate | Require explicit repo and preload inputs so data loading stays visible and caller-controlled. |
| T-03-08 | Tampering | hydration identity | high | mitigate | Use an explicit source-row identifier for hydration and avoid depending on custom document-id semantics that are meant for index identity. |
| T-03-09 | Repudiation | stale-row handling | medium | mitigate | Surface `missing_ids` in the public result so stale index drift is observable instead of silently suppressed. |
</threat_model>
