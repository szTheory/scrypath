# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase has no product UI. The public-facing surface is the README, ExDoc output, Phoenix guides, code examples, and release-facing polish. Preserve the existing ExDoc shell and tighten the content hierarchy, example flow, and Phoenix-first wayfinding inside those surfaces.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | Remix Icon through existing ExDoc output |
| Font | Lato for rendered docs, system sans fallback elsewhere |

Implementation note: Phase 6 should use the existing ExDoc presentation layer from `mix.exs` and `doc/dist/*` rather than introducing a custom site, React stack, or third-party registry.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline code padding, badge gaps, punctuation-adjacent icon spacing |
| sm | 8px | List spacing, compact callout padding, code annotation gaps |
| md | 16px | Default paragraph separation, block spacing, table cell padding |
| lg | 24px | Section spacing inside guides and README subsections |
| xl | 32px | Major guide breaks, code-example to explanation spacing |
| 2xl | 48px | Top-level doc section separation |
| 3xl | 64px | README hero-to-next-section and page-level section breaks |

Exceptions: 44px minimum target for icon-only controls exposed by ExDoc, and horizontal scrolling is allowed for code blocks and wide tables instead of wrapping long tokens.

---

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 700 | 1.4 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.2 |

Rules:
- Use only weights `400` and `700`.
- Keep prose dense but calm: short paragraphs, no banner-style marketing copy.
- Code examples remain monospace at the ExDoc default scale and should never be reduced below body-legible size.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | README background, ExDoc content background, primary reading surface |
| Secondary (30%) | `hsl(207, 43%, 96%)` | Sidebar, callout backgrounds, table headers, code-block chrome |
| Accent (10%) | `hsl(250, 68%, 59%)` | Inline links, active table-of-contents state, tab focus, primary code-copy affordances |
| Destructive | `hsl(7, 80%, 40%)` | Warning callouts for cutover, delete, or irreversible operator actions only |

Accent reserved for: first-link emphasis in opening sections, active navigation state, focused interactive controls, and the title line of Phoenix-specific callouts. Do not use accent as a broad fill color for whole sections or decorative brand treatment.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Read the Phoenix guide |
| Empty state heading | No Phoenix integration example yet |
| Empty state body | Start with the context example, then wire the same search call into a controller or LiveView. Keep repo access and indexing decisions in the context layer. |
| Error state | This example assumes a configured repo, backend, and searchable schema. Verify setup, then rerun the example or open the matching guide section before changing code. |
| Destructive confirmation | `cutover?: true`: Review counts, sampled queries, and settings on the target index before cutover. Do not present cutover as a harmless toggle. |

Voice rules for this phase:
- First mention on every public page uses a descriptor: `Scrypath, the Ecto-native search indexing library` or `Scrypath for Phoenix & Ecto`.
- Phoenix examples must show explicit context calls from controllers and LiveView modules. Do not imply hidden callbacks, model hooks, or magic synchronization.
- When discussing sync, reindex, or visibility, prefer precise operational wording over optimistic verbs like "instantly" or "automatically fixed."
