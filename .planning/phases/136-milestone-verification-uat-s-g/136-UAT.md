## UAT Protocol

Review in this order:

1. **Dark first:** use the live lane and screenshot artifacts to inspect every
   required surface in dark mode before making any light-theme judgment.
2. **Light parity:** repeat the same job checks in light mode and compare the
   same evidence claims instead of accepting a weaker light experience.
3. **System-dark evidence:** review system-dark proof in `136-DUALVERIFY-REPORT.md`;
   do not force `localStorage["phx:theme"]` for this check.
4. **Before/after compare:** compare the claim rows in `136-BEFORE-AFTER.md`
   with the generated screenshots under the screenshot artifact root.
5. **Classify findings:** every issue must be marked `must-fix`, `accepted follow-up`,
   or `blocked`. Approve only if no D-18 must-fix blocker remains.

## Finding Classification

Use D-18 for `must-fix` blockers:

- failing required command or browser gate
- AA contrast failure or disabled/suppressed color-contrast rule
- focus not visible, obscured, trapped incorrectly, or not returned
- reduced-motion regression or LiveView patch-refiring motion
- stale asset proof, wrong server lane, missing seed proof, or screenshot count/checksum mismatch
- visual defect blocking trust, scanability, task orientation, or light/dark/system parity

Use D-19 for `accepted follow-up` only when the issue does not affect trust,
accessibility, scanability, focus, reduced-motion, or theme parity.
