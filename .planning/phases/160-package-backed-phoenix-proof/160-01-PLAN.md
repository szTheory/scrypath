<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Maintainer environment → Mix task | Environment contains service URLs and may contain credentials; command output and temp artifacts cross this boundary. |
| Mix task → filesystem/subprocesses | Task creates an isolated root, runs Mix/Git commands, and stages an example that must resolve only to the package artifact. |
| Staged Phoenix test app → Postgres/Meilisearch | Existing integration tests send real data to the configured local services and clean their unique test indexes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-160-01 | Information disclosure | Mix task output and retained temp root | medium | mitigate | Never dump environment; redact sensitive configured values from captured output; isolate empty HEX_HOME/MIX_HOME and retain no credential files. |
| T-160-02 | Tampering | Staged example dependency and artifact handoff | high | mitigate | Build/unpack in a unique owned root, stage without build/dependency caches, assert no path source, and require the lock entry to name the artifact file URL and version tag before compile/test. |
| T-160-03 | Denial of service | Temp workspace lifecycle | low | mitigate | Bound cleanup to the unique task-owned root and remove it in an after path unless a failed run explicitly requested retention. |
| T-160-SC | Tampering | Existing locked Mix/Hex dependencies fetched for the staged example | medium | mitigate | Add no dependencies or version changes; use the existing lockfile and isolated empty Mix/Hex homes, and prove Scrypath resolves from the local package artifact. |
</threat_model>
