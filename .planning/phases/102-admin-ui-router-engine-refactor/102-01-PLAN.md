<task type="auto">
  <name>Task 2: Implement AssetPlug</name>
  <files>scrypath_ops/lib/scrypath_ops_web/plugs/asset_plug.ex</files>
  <action>
    Create `ScrypathOpsWeb.AssetPlug` using `Plug.Conn`. It should handle requests for pre-compiled assets from `priv/static`.
    Specifically, it should be able to serve files like `/assets/css/app.css`, `/assets/js/app.js`, and `/images/logo.svg` by reading from `Application.app_dir(:scrypath_ops, "priv/static/" <> path_info)`.
    Ensure the plug sets appropriate content-type headers (e.g., using `MIME.from_path/1`) and cache-control headers. Return 404 if the file is not found.
    Analog Reference: Although PATTERNS.md maps an `AssetController` based on the pattern of `ScrypathOpsWeb.PageController`, this plan intentionally implements an `AssetPlug`. A raw Plug using `Plug.Conn` is more idiomatic and lightweight for embedded static file delivery than a full Phoenix controller. Use `Plug.Conn.send_download` or `Plug.Conn.put_resp_content_type` and `File.read!` as mapped in the analog's file-I/O role.
  </action>
  <verify>
    <automated>cd scrypath_ops && mix compile</automated>
  </verify>
  <done>Plug exists and compiles.</done>
</task>
