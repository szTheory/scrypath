<objective>
Ship **`Scrypath.search_within_facet/4`** and **`Scrypath.search_within_facet!/4`** as thin delegates over the existing **`search/3`** pipeline: merge **`{facet_attribute, value}`** into **`opts[:facet_filter]`** with **D-06** conflict rejection, extend **`Telemetry.common_metadata/3`** usage so scoped searches emit **`search_scope: :within_facet`** and **`scoped_facet:`** (facet attribute atom), and add **`test/scrypath/search_within_facet_test.exs`** with **Req.Test** payload assertions plus a conflict **`ArgumentError`** test — all per **`38-CONTEXT.md`** D-01–D-07, D-09–D-12.
</objective>

<threat_model>
**ASVS V5.1 L1 — logic integrity (library)**

| Threat | Severity | Mitigation |
|--------|----------|------------|
| **T-38-01:** Mis-composed filters return **wrong hit sets** (catalog leakage or empty results) | High | Reuse `Query` + `Meilisearch.Query.to_payload/1`; integration test asserts JSON `filter` / `facetFilters`; conflict raises instead of silent merge |
| **T-38-02:** Operators cannot tell scoped vs plain search in telemetry | Low | Attach `search_scope: :within_facet` and `scoped_facet:` to metadata on the existing `[:scrypath, :search]` span only for the scoped entry (no duplicate spans) |

</threat_model>
