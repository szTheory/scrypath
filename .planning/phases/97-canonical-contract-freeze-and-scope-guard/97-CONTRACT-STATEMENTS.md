# Phase 97 Canonical Contract Statements

## CST-TRUTH-01-INSTALL

Canonical statement:

> Scrypath adopter-facing install guidance uses one release-backed version contract across high-risk entry surfaces. Any `main`-branch setup is explicitly marked as unreleased branch-tip behavior and is not presented as stable release guidance.

Owner surface: `guides/support-and-compatibility.md`

Reference surfaces:
- `README.md`
- `CONTRIBUTING.md`
- `guides/outside-adopter-intake.md`

## CST-TRUTH-02-RELEASE-MAIN

Canonical statement:

> Scrypath contract surfaces must clearly separate release-backed instructions from `main` branch behavior. `main` may contain unreleased changes, and stable adopter usage points to release-backed artifacts.

Owner surface: `guides/support-and-compatibility.md`

Reference surfaces:
- `README.md`
- `CONTRIBUTING.md`
- `guides/outside-adopter-intake.md`
- `docs/releasing.md`

## CST-TRUTH-03-SUPPORT-AUTHORITY

Canonical statement:

> `guides/support-and-compatibility.md` is the single canonical adopter-facing support and compatibility authority. Other entry surfaces route to that guide for normative policy text instead of re-declaring competing support matrices.

Owner surface: `guides/support-and-compatibility.md`

Reference surfaces:
- `README.md`
- `CONTRIBUTING.md`
- `guides/golden-path.md`
- `guides/outside-adopter-intake.md`

## Phase boundary

These canonical statements are contract-hardening inputs only. They do not authorize runtime capability expansion, backend broadening, or new public runtime API categories in Phase 97.
