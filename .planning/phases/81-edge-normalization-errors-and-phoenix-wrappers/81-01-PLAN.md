<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser params -> `Scrypath.QueryParams.normalize/1` | Untrusted nested request input crosses into owned Scrypath namespaces. |
| `QueryParams.Caster` -> `Scrypath.Options` validators | Converted browser data must not widen or bypass the canonical runtime grammar. |
| normalized plain data -> `Scrypath.search/3` | The new edge helper must prepare data only and must not become a second executor. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-81-01 | T | `lib/scrypath/query_params/caster.ex` | mitigate | Use explicit allowlists for top-level and nested owned keys per D-01..D-08; reject unknown nested keys with structured issues instead of silently accepting extra semantics. |
| T-81-02 | D | `lib/scrypath/query_params/caster.ex` | mitigate | Never call `String.to_atom/1` on request input; convert only known public keys and facet/sort operators through bounded mappings. |
| T-81-03 | I | `lib/scrypath/query_params/error.ex` | mitigate | Keep errors field-scoped and machine-readable without leaking runtime-only internals such as `%Scrypath.Query{}` or Phoenix/Ecto-specific structures. |
| T-81-04 | E | `lib/scrypath/query_params.ex` | mitigate | Preserve `Scrypath.search/3` as the only executor and prove parity through tests so the normalization API cannot drift into a higher-privilege runtime facade. |
