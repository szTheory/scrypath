# CI and CD efficiency ledger

Standing rule: [AGENTS.md "CI and CD efficiency"](../../AGENTS.md). Every CI, release, deploy or bot-PR run is looked at for low-hanging speed, iteration-time and cost wins that do not weaken what a check proves. This file is where measured findings, candidates and decisions live. Newest findings first. A candidate is not a decision: apply the low-risk ones in the next CI change, and write the outcome next to the row.

How to measure: `gh run view <run-id> --json jobs --jq '.jobs[]|[.name,.conclusion,((.completedAt|fromdateiso8601)-(.startedAt|fromdateiso8601))]|@tsv'` (skipped jobs have a zero timestamp, filter them out), and `gh run view <run-id> --log-failed` for failures.

## Local-first checklist (before waiting on hosted CI)

1. `mix format --check-formatted <files>` and the one test file you changed.
2. Token and pair tests: `node --test examples/scrypath_ecommerce/ui-tokens.test.mjs scripts/ci/ui_state_pairs.test.cjs` (about 1 s).
3. Package changes: `mix verify.package`. Docs changes: the built-docs contract in `test/release/package_metadata_test.exs`.
4. Static analysis: `MIX_ENV=test mix dialyzer` (about 35 s with a warm PLT; run `mix deps.get` first after a lock change). Found two real errors on 2026-11-20 that the hosted advisory lane had been hiding.
5. Workflow wiring: `act -l -W .github/workflows/ci.yml` lists the jobs (act 0.2.87 at `/opt/homebrew/bin/act`, verified 2026-11-20); `act -j <job> --container-architecture linux/amd64` for the cheap jobs (`backend`, `package`, `core`) with a pinned image that has a working Beam/OpenSSL stack. Not yet measured end to end; record the first real run here. The browser lanes (`ecommerce-mounted`, `ecommerce-e2e`) need the repository's own Docker wrappers, not `act`.
6. A change to anything the verifier fixture copies: run the whole CI Node step locally (`.github/workflows/ci.yml`, "Verify browser build, lifecycle, evidence, and target behavior").
7. A shallow checkout (the `package` job) lacks history: tests that use `git merge-base` or `git show` must handle that (the README header pin test does).
8. The browser-lane path classifier works offline: `GITHUB_EVENT_NAME=pull_request GITHUB_BASE_REF=main node scripts/ci/ecommerce_path_classifier.cjs --head <ref>` prints `run=false` only when every path changed on `<ref>` over `origin/main` is under `.planning/`, under `docs/`, or a root-level markdown file.

## Findings and candidates

1. **An always-red advisory lane hides new reds (found 2026-11-20).** `deep-quality (advisory)` fails on every run because of the known cloak and cloak_ecto advisory, and that masked two new dialyzer errors from Phase 186's brand tooling (`refuse!/1` in `dev/mix/tasks/brand/update.ex`, `fail!/2` in `dev/mix/tasks/verify/brand.ex`: "has no local return"). They had been red since 2026-11-19 with nobody looking. Fixed with `@spec ... :: no_return()` (the same pattern as `verify.release_parity`). Candidate: split the lane so dialyzer and the other deep checks report as their own advisory job and only the dependency audit stays red for the known cause (or make the dependency audit its own job), so the lane is green when only cloak is wrong. Quality gain, small cost change. Status: candidate.
2. **Planning-only and docs-only PRs pay the full 19 minutes.** PRs #144 (`.planning/` only) and #145 (README, docs and one test) each ran `ecommerce-mounted` (1134 s) and the whole `repository-contracts` Node step. `ops-ui-path` already shows the pattern: a classifier job and a job-level `if`, so the required context still reports as skipped-green. Candidate: add an `ecommerce-path` classifier and skip `ecommerce-mounted` (and the Node step of `repository-contracts`) when only `.planning/**`, `docs/**`, `*.md` and tests that those lanes do not read changed. Must keep `workflow_wiring_test` passing and must not skip when `brand/`, `scrypath_ops/`, `examples/`, `scripts/ci/` or workflow files change. Estimated saving: about 19 minutes of wall time and about 35 runner-minutes per docs-only PR. Risk low to medium (path list correctness). 

   **Outcome: implemented in Phase 188.1 (this phase's PR), not yet measured on a hosted run.** Status: implemented, saving unmeasured.

   - **Mechanism.** A new `ecommerce-path` job (full-history checkout, then `node scripts/ci/ecommerce_path_classifier.cjs --output "$GITHUB_OUTPUT"`) writes `run=true` or `run=false`. It is an allowlist that fails open: `run=false` only when the event is a `pull_request` and every changed path is under `.planning/`, under `docs/`, or a root-level markdown file. One other path, an empty diff, a diff it cannot compute, any error, and every push, schedule, dispatch or merge-group event gives `run=true`. A rename counts both its old and new path, so moving `lib/x.ex` to `docs/x.md` still runs the lanes. It gates `ecommerce-mounted` (job-level `if`, so the required context still reports as skipped-green) and exactly two steps of `repository-contracts` (the demo dependency install and the browser Node step). `repository-contracts` keeps a job-level `!cancelled()` so a failed classifier cannot skip the required job, and `mix verify.repository_contracts` always runs. Consumers compare with `!= 'false'`, never `== 'true'`, so only an explicit `run=false` from a successful classifier skips anything. No required check was added or renamed (the gate ledger in CONTRIBUTING.md still reads 8 of 12).
   - **Measured before (quoted from the table above, PRs #144 and #145).** About 19 minutes wall; `ecommerce-mounted` 1134 s; the `repository-contracts` Node step about 575 s; about 35 runner-minutes for the whole docs-only PR.
   - **Measured after.** Not yet measured on a hosted run. This PR touches `.github/workflows/ci.yml` and `scripts/ci/`, which are not on the allowlist, so the classifier correctly runs every lane on it and cannot show the saving. The skip path is proved instead by the planted-diff tests in `workflow_wiring_test` and `scripts/ci/ecommerce_path_classifier.test.cjs`, and by a real-data local check: `GITHUB_EVENT_NAME=pull_request GITHUB_BASE_REF=main node scripts/ci/ecommerce_path_classifier.cjs --head main` reported `run=false` for local `main` over `origin/main` (30 changed paths, 29 under `.planning/` plus the root `AGENTS.md`, recomputed at execution time), and `run=true` for this branch's own diff.
   - **Expected saving (an estimate from this ledger's own timings, not a result).** About 12 minutes of wall time on a docs-only or planning-only PR: the 19-minute before-wall minus about 7 minutes for the longest lane that still runs (an advisory compatibility cell, up to 395 s). About 28 runner-minutes: `ecommerce-mounted` 1134 s plus the Node step about 575 s. The 35 runner-minutes above is the whole docs-only PR cost, not the saving.
   - **Costs it introduces, unmeasured.** One extra job (a full-history checkout plus a node start, estimated tens of seconds) now sits ahead of `ecommerce-mounted` and `repository-contracts`, and both wait for it. Code PRs therefore gain roughly the classifier job's duration on the critical path (estimated tens of seconds; `ecommerce-mounted` stays the critical path at 1134 s). Measure it on the same run as the saving.
   - **Allowlist evidence (reader grep, 2026-11-20, re-run at execution).** Over `scripts/ci/ecommerce_*.cjs` (excluding the classifier and its own test, which name the allowlist paths by design and run only in the always-on contract lane), `scripts/ci/ui_state_pairs*.cjs`, `dev/mix/tasks/verify/ecommerce_mounted.ex` and `examples/scrypath_ecommerce/e2e/`, the only mentions of `README`, `CHANGELOG`, `CONTRIBUTING`, `docs/` or `.planning/` are two comments in `e2e/ops_host_contract.spec.ts`. `ecommerce_build.test.cjs` only asserts `.planning` is in `.dockerignore`. `examples/scrypath_ecommerce/scripts/reskin-capture.mjs` names `.planning/`, but no workflow, `mix verify` task or CI script runs it (it is a local preview tool behind npm scripts). `ui-tokens.test.mjs` scans `docs/` and root markdown inside ExUnit lanes (`core`, and the mix step of `repository-contracts`) that are never skipped. No lane reads allowlisted content, so the allowlist was not shrunk.
   - **Measurement plan.** On the next planning-only or docs-only PR after this merges, record `gh run view <id> --json jobs --jq ...` timings (the command is in the header above), confirm every required context reported success while skipped (`ecommerce-mounted` skipped, `repository-contracts` green), and replace the estimate above with the measured numbers and the classifier job's own duration. Until then this entry stays "not yet measured on a hosted run".
   - **Revisit trigger.** Re-read the allowlist when any Node or browser lane, or `mix verify.ecommerce_mounted`, starts reading `docs/`, a root `*.md` file or `.planning/`. Delete the classifier (and the two gates) if it goes a quarter without a docs-only or planning-only PR, since it would then cost a job per PR for no saving.
   - **Follow-ups after merge (shipping steps, not done here, not claimed).** The orchestrator runs `gh pr update-branch 132`, merges Dependabot #132 on green (the `upload-artifact` bump the new pin pattern accepts), and re-runs #129 on the re-skinned base. Those outcomes are recorded in `188.1-01-SUMMARY.md` first and then in STATE.md, only once verified after the merge.
3. **Compatibility matrix on every PR.** Four advisory cells, about 22 runner-minutes, on PRs that cannot change compatibility (planning, docs, website). Candidate: gate them behind a `lib/`, `mix.exs`, `mix.lock` path classifier on PRs and keep them on schedule and push to `main`. No required check involved. Status: candidate.
4. **Serial strict merges for bot PRs.** About 20 minutes each. Candidates: a merge queue (batches and tests the combined result once), or keep `strict` but group Dependabot more aggressively so there are fewer PRs; do not drop `strict` without a decision, because it is a quality control. Status: candidate, needs the maintainer's call on branch protection.
5. **Website `build-and-check` install time.** About 8 of 8.5 minutes is the browser install (per the v1.47 website note). Candidate: cache the browser or drop `--with-deps`; measure in the Phase 189 plan. Status: candidate, folded into v1.47 Phase 189.
6. **Repository-contracts Node step.** 575 s of 823 to 858 s, mostly `ecommerce_lifecycle`. Candidate: split the step into a parallel job so it overlaps `ecommerce-mounted` (the critical path is already `ecommerce-mounted`, so this only helps once finding 2 lands). Status: candidate.
7. **Advisory nightly that is always red.** `ecommerce-e2e` nightly failed 7 of 8 times unnoticed (standalone copy specs, one failure inspected). A lane nobody reads costs 23 minutes a night and trains everyone to ignore red. Candidate: read it, fix or delete the failing specs, and surface a nightly failure somewhere it is seen. Status: candidate, read the 2026-11-20 nightly first.
8. **Release run.** Release Please opens its PR automatically since the 2026-11-20 repository-setting fix. A bot-authored release PR gets no CI until a human-authored event; `gh pr update-branch <n>` triggers it without close-and-reopen and also brings the branch up to date in one call (used for 0.3.19). Record the publish job's timings after the 0.3.19 release below.
9. **`ops-ui-path` fails closed the wrong way (found 2026-11-20 while planning Phase 188.1).** Its step pipes `git diff --name-only ... | grep -qE ...`, so a diff command that errors produces no matching line and the step writes `run=false`, which skips `ops-ui` (a required context) on an error. The new `ecommerce-path` classifier computes its diff inside a script and turns any error into `run=true`. Candidate, low priority: move `ops-ui-path` to the same fail-open shape. Not changed in Phase 188.1. Status: candidate.
