# Pitfalls Research

**Project:** Scrypath v1.41
**Updated:** 2026-09-28 after fanout review

| Observed pitfall | Consequence | Bounded prevention |
|---|---|---|
| Treat Mint 1.10.1 as currently fixed | Today's advisories also affect the root graph | Refresh primary advisories; target 1.11.0+ across four graphs and necessary HPAX resolution. |
| Audit only root | Three maintained consumer locks are invisible to that result | Audit the explicit graph inventory repeatedly in the existing advisory lane, guard omissions, retain each lock/result identity and measure incremental cost. |
| Check package Git tag but ignore post-resolution Hex entries | Passing consumer scenarios can silently prove a different dependency graph | Preserve/compare expected Hex entries and report effective Mint/HPAX; focused in-process drift regression. |
| Treat green manual closeout as Ops proof | Ops is skipped on that event | Inspect the existing PR/main Ops result for its actual source. |
| Commit a large accumulated branch as one delivery | Small code fixes are buried in planning history and unrelated local edits | Clean public-main base, owned-source inventory and coherent PRs. |
| Complete a delivery requirement with an unmerged PR | Public bug fixes remain unavailable | Require selected fixes on green main; report blocked merge/release or explicit owner deferral. |
| Refresh every new bot PR until the inbox is empty | Work never terminates | Freeze a dated cohort; new routine items enter maintenance. |
| Remove every README summary | First-hour adopters lose essential consistency context | Preserve short first-result route and caveat; consolidate full contracts and update only obsolete assertions. |
| Write another assessment after every final attestation | Each tracked write creates another unverified source | Freeze tracked inputs, attest final source, then a durable external terminal decision; no fabricated semantic PASS. |
| Reopen the whole product because a probe lacks a descriptor | Missing context becomes endless product work | Use the finite existing baseline, named workflows and concrete invalidators; retain limits and explicit dispositions. |
| Call root lock a published security minimum | Consumers assume their own lock was fixed | State repository graph scope and host-owned resolution; no unsupported public dependency promise. |

No new required lane, broad matrix, exhaustive exploit suite, or generic audit project is justified. Read [SUMMARY.md](SUMMARY.md) and the specialist reports for source-level evidence, alternatives and the selected approach.
