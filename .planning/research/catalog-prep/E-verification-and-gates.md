## 3. Journey and handoff (decision, confidence 0.8)

Live in `scrypath_ops/test/scrypath_ops_web/live/catalog_journey_test.exs` with `Phoenix.LiveViewTest`, reusing the stubs and the `:failed_sync_insert_counter` Agent that `failed_sync_live_test.exs` already uses. One path: Search health row -> Failed sync prefilled with the same index and run (assert the carried facts in `has_element?` and in the URL params, not in a screenshot) -> retry (assert the changed field text and exactly one insert) -> return link back to Search health with the same context. Denial: same retry event, schema removed from the allowlist (`That schema is unavailable.`, counter 0) and stale sudo (redirect carries `return_to`, counter 0). Absence of protected details: the denied HTML must not contain the never-index fixture's field values (assert a sentinel string from the fixture is absent, with the positive control that it IS present when allowed). Positive control: the identical action with the allowed viewer produces counter 1; without it a denial test passes vacuously. Playwright only for keyboard order and focus-after-return, deferred to check 10's later growth. Rejected: a Playwright journey (C23 says stories prove existence, not function; LiveViewTest folds real events); a viewer-role model (none exists in source, do not invent one for a catalog).

## 8. Adversarial pass

- Check 3 could pass while the real storybook breaks, since it renders through our helper. Mitigation is the two real-route GETs; cheapest disproof: break an `attr` default in a planted story and confirm both go red.
- Route mounted in test (needed for the real-route GETs) differs from C28's "dev only". Prod absence is proven by check 1, so I accept test mounting; if the maintainer wants dev only, drop the real-route GETs and keep the helper (confidence 0.65).
- Check 4 via `__components__/0` uses a `@doc false` Phoenix API. Fallback is public `__info__(:functions)` filtered by arity 1 with a declared `attr`; a Phoenix bump that removes it fails loudly.
- Check 10 may be flaky (iframe load, font swap). Early warning: two non-defect reds in 30 days drops it. Wait on the story element's own selector, not on timeouts (C20).
- The whole set cannot show the screens are coherent (C32). That stays with the maintainer's milestone-end review and is not claimed as automated evidence.

## 9. Phase and plan implications

Order by cost and risk: (1) boundary extension and flip (check 1, 2) land in the spike PR with the dependency, before any story exists; (2) checks 3 to 8 land with the first story PR, so no story merges ungated; (3) the journey with the pilot; (4) check 10 local script after the pilot, advisory CI job only if its numbers justify it. One plan can hold checks 3 to 8 (one file, about 250 lines); one holds the journey; one holds 1, 2 and 7's source scan. This keeps the cap of 5 per phase.

Cross-area flags: fixtures must export `viewer` and a never-index sentinel for section 3; the router agent must decide route-in-test (section 8); adopter theme tokens must live outside `scrypath_ops/lib` and `assets` (literal ratchet); screen-tier stories must name a production function or LiveView so check 4 can map them.
