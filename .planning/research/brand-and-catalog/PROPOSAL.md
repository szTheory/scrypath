## What accrue taught us (read 2026-11-18; code and history, nothing run)

Headline: accrue made its new brand render in 2 days (phases 255-256, about 45 commits) and has spent 13+ days (about 600 commits) making whole screens coherent. A complete inventory (83 catalog entries, 2,970 browser cases) and green gates still produced screens the owner called "ugly noise". Accrue also built storybook baselines for its old identity, then the owner said not to polish soon-to-be-replaced screens.

Changes this makes to the plan:
1. **Re-skin before catalog.** Do not build stories or baselines against the old identity. The token swap is cheap and mostly mechanical; do it first, then the catalog and the pixel-identical extraction run against the new look. (Draft r1 had this the other way round.)
2. **Commit the book into the repo before planning against it.** Accrue planned against an untracked BRAND.md for six days.
3. **Prove one whole task end to end before scaling.** A coherence check on one job (JOB-03 fix failing sync, across Failed sync work and Search health) comes before expanding story matrices. State what each gate proves; "green" is not "good".
4. **Automated stand-ins for "is this screen coherent"** (required by our no-human-UAT rule; accrue's owner waived manual review but its agents still needed these): banned-token tests (raw booleans, UUIDs or internal predicate names as primary text), a fact-count budget per page header, one h1 per page, no duplicate nav labels, a typographic role per region, a review ledger whose assessment fields must be filled with sabotage controls, and matched before/after captures per scenario.
5. **Token source of truth, both directions.** Accrue's v2 palette was hand-copied into CSS with no parity check; its older DTCG harness only read old scopes. For Scrypath: each token in `brand/tokens.json` maps to an Ops token with an explicit derivation; compare resolved values both ways over light, dark, and the system-dark media block; deny-list the retired hexes (violet, copper, #aaa0ff, dark floor) across `app.css`, built assets, storybook CSS, e2e and tests, with a sabotage case; add a browser computed-color check (a static mirror cannot see cascade tails); check that committed built CSS and the composed storybook CSS are fresh.
6. **Scope every token to the Ops root** so nothing leaks into host or global CSS. Scrypath replaces the default, so no opt-in profile is needed; add a test that a host accent override still wins and that mounted paths work.
7. **Verify settled, composited styles** across saved theme, switch, reload and navigation. Accrue shipped a saved-dark cookie bug that passed token math and the user's acceptance and was only caught by screenshots.
8. **Catalog entry model** (copy from accrue): stable ids, one tier each (Primitive, Pattern, Area, Screen, Flow), a state matrix of `{name, applicable, reason, source, story}` where impossible states are recorded with a reason and not rendered, derived (not hand-written) Primitive and Pattern entries from the component registry, one fragment module per area, `data-catalog-entry/state/tier` markers, and a bidirectional parity test (router, nav, story files, registry against entries; rendered section ids against declared anchors). Add persona, twin and job fields. Generate as much as possible: accrue's 9,000 hand-written lines are an anti-goal.
9. **Mounting whole screens:** static `:page` stories that render the production LiveView's `render/1` as a function component with plain assigns (`Phoenix.LiveViewTest.__render_component__`, a double-underscore API, so the spike must check its stability on LiveView 1.1.x). This needs each LiveView to expose a `*_page/1` function component with declared attrs and async loads reduced to plain loading/error assigns. Accrue needed it for 2 of its LiveViews; Scrypath's Failed sync, Search and Sync and index are monoliths, so budget 1 to 3 days each, proven pixel-identical. No story-only flags in production code.
10. **Language catalog and lint:** a JSON source with a thin Elixir module that generates functions (zero-arity ones export to e2e and stories automatically); closed vocabularies first; a resource-by-state generator for empty, loading, filtered-empty, unavailable, permission-denied and error copy (this is what kills the "Nothing at risk." bug class where copy is wrong in one data state); a `locked` field with an acknowledgement test; an AST pass over `~H` sigils that flags unregistered text nodes and `aria-label`, `title`, `placeholder`, `alt` attributes, with a per-file shrink-only baseline; `put_flash` and string-literal labels in `.ex` files. Accrue has no such lint (about 40 to 45 percent of its newer detail-page strings are still inline literals), so do not assume its approach scales without it. Avoid function-per-string modules, hand-kept export allowlists, a second hard-coded copy of locked strings in e2e, and naming code after planning phases.
11. **Evidence pipeline checklist, design in advance:** raw receipts in CI artifacts, only a small digest manifest committed (accrue committed a 46 MB evidence JSON); one parameterized evidence directory contract tested against both preflight and recorder; selection manifest generated from source dependencies, with always-run sentinel cases and a global-roots fallback (do not hand-restamp digests; accrue has about 35 deviation records); measure the real border-box width before axe; scope wrapper CSS to the real ancestry; never run fixture-mutating tests and a preview server on one database; avoid a module-wide DB transaction in test setup (the 126 s fixture overran a 120 s lease).
12. **Fixtures:** realistic by default, stress data in separate named states.
13. **Storybook theme:** do not copy a separate dark palette; put sandbox selectors beside the production selectors in the same CSS blocks. Wait for `.phx-connected` before sending a color-mode event. Page stories do not get the dark class from storybook's own hook; mirror it. Keep the storybook JS hook-only (no second LiveSocket); mirror CSS custom properties onto overlay roots, since portals sit outside the sandbox.
14. **CI cost:** accrue's required storybook job takes about 17 minutes and its full matrix 12 minutes locally. Scrypath's lean posture (required: render and parity gates in seconds; browser sweep advisory and nightly until it has run clean for 14 nights) is a deliberate divergence.
15. **Fonts:** self-host subset latin woff2 with the OFL notices, a finite descriptor list and byte-derived cache hashes; pin hashes in tests; ship-test the Hex archive; same-origin fonts avoid CSP changes. Mind that the committed built CSS is what ships.
16. **Do not** spend on a logo tournament, expand thousands of placeholder cases, put a skin on storybook's own shell, or treat inventory completeness as design quality.

## What sigra taught us (read 2026-11-18; two surveys, nothing run; full provenance in `.planning/reference/BRAND-ADOPTION-PLAYBOOK.md`)

- **Order.** Sigra went baseline first (259 pin and compatibility, 260 deterministic before-catalog, 261 re-skin; 41 plans, about 4 days). Its text-only before catalog never caught a visual regression; the guards in the visual phase were a reviewed old-to-new token table with table-to-CSS and table-to-book tests, 30 contrast pairs bound to the real stylesheet and a frozen-names ratchet. The catalog paid off later as scope containment in the wording phase ("exactly these seven screens changed"). Sigra's own agent recommends Scrypath do "mechanism before paint": re-skin first, no PNG baselines on the old identity, plus the cheap pieces below. This supports the revised order above.
- **Cheap pieces to copy into v1.46:** a reviewed old-to-new token mapping table with table-to-CSS and table-to-book tests; the book's contrast pairs bound to the real stylesheet; planted in-memory failure controls; a visible pixel-compare kill switch for the v1.45 preservation specs so the first visual PR is mergeable (sigra hit a canary deadlock; reasoning verified by reading only); never recapture screenshots on macOS; run CI shell filters under the CI image.
- **Skip:** the immutability manifest, privacy normalization ceremony and the 18-plan compatibility phase. ScrypathOps is internal; the existing literal ratchet already pins names, so add only the line "values may change, names may not".
- **Logo sign-off** was a human contact sheet at 96, 120 and 192 px and favicon frames at 16, 24 and 32 px. Automated substitutes prove bytes and geometry, not "distinct" or "legible"; Scrypath needs mechanical criteria (minimum stroke at 16 px, perceptual-hash distance from the old mark) or an explicit owner exception.
- **Blocked states (Sigra-gated actions).** Today ScrypathOps shows no persistent blocked UI: Retry, Delete saved search and Promote are always enabled, and a block appears only after the click as an error flash or a redirect to the host's sudo page. Three of the six configured gated actions have call sites (`:failed_work_retry`, `:swap_live`, `:saved_search_delete`); `:reindex`, `:delete_documents` and `:hot_apply` are reserved. Seven outcomes exist (allowed, unverified identity, impersonating, step-up needed, sudo invalid, session malformed, integration unavailable), all with one shared copy and no per-action wording; the "impersonation" literal is duplicated. Plan: extract a pure `decide/4` with typed reasons, a copy entry per reason, a scenario fixture driven from the existing `OperatorContext` struct (already constructible without Sigra), and tests that every gated call site has allowed and blocked stories. A visible disabled-with-explanation state before the click is a product change to decide separately.
- **Copy bugs worth the lint:** "Index promotion blocked: " is prefixed onto text that already says "Promotion is blocked: ..." (`sync_drift_live.ex` about line 290); `inspect(reason)` leaks into retry and swap flashes (`failed_sync_live.ex:352`).
- **Copy scanner:** do not copy sigra's hand-rolled byte scanner (two fix rounds for fail-open bugs, six hand-listed attributes, no `.js`, negative-only). Use `Code.string_to_quoted` and the LiveView tokenizer (private; pin and wrap), derive copy attributes from `attr` declarations, allow a positive "must come from the catalog" mode, per-file shrink-only baseline keyed without line numbers, regeneration refused in CI. Estimated 2 to 3 days.
- **Glossary enforcement:** parse `GLOSSARY.md` (`**Term**` and `_Avoid_`) into rules, add a scope sidecar for qualifiers such as "outside setup and access errors", test that every avoided term has a sidecar row, count rows left editorial.

## What threadline taught us (read 2026-11-18; three surveys, nothing run; provenance in the playbook)

- **Order.** Threadline interleaved: map jobs and routes, then brand tokens plus one whole ordinary task, then remaining screens, then catalog. It reached a branded whole-journey admin in about 3 days (v1.48, phases 248-253, 36 plans, PR #105) but got a poor catalog (coarse stories, notes inside previews) and needed three more milestones. Combined with accrue and sigra: every project says prove one whole task before scaling, and none got the catalog right by leaving it for last. Our plan keeps re-skin first and now fixes the catalog structure (one component per story, notes outside previews, stable variation ids) in the first catalog phase.
- **Whole-task pilot gate (v1.47 phase 193) is now specified.** Choose the walkthrough from existing research and pin its data in the phase context (JOB-03: a failing sync on a named schema, through Search health to Failed sync work, retry, and back with filters restored). The gate is one browser test with no human: exact values, URL and filter state, a canary that must never reach rendered text, return via UI links, a computed-style check on type sizes and focus ring, a text-range wrap check (threadline's "Close" label wrapped to 5 lines while width checks passed), and a custody check on before and after captures (same data, same browser identity, digests of the served CSS and fonts). Keep before and after evidence on a durable path, not `/tmp`. Budget for a large helper; threadline's was 2,389 lines and the phase about 16 hours.
- **Token parity test.** Read approved brand data, check dark, light and system-dark lanes, use at least three mutation controls, rewrite old pins deliberately with "Superseded historical identity" markers.
- **Agent review.** Two roles (source, copy and security; visual), a disposition table, source frozen until reviewers return, visual findings verified against pixels. It is judgment, not proof.
- **Storybook location.** Inside `scrypath_ops` (ADR 0001), with a root test that the published `scrypath` package never mentions storybook, a test that prod config and routes exclude `/dev/storybook`, a dev-routes-only gate, and no router fallback stub. Do not copy accrue's in-package dev modules or threadline's example-app indirection.
- **Fixtures and blocked states.** Coherent ordinary data separate from allowlisted stress cases; do not mirror a big stress registry. Denied, unavailable, stale and reconnecting are static renderer states; real authorization is tested in LiveView tests. This matches the pure `decide/4` plan for the Sigra-gated actions.
- **Browser lane.** Keep it small: one bounded smoke per story family at 320 and 768 px through an existing script. Threadline's "bounded" smoke grew into a 4,588-line spec with per-story screenshots, and committed traces. Measure CI before adding a lane.
- **Overlays in static previews** need explicit widths and render-only-when-shown (threadline's toast measured 34 px wide until fixed). Budget retries.
- **Copy.** A rendered-page copy contract test (forbidden vocabulary, no exclamation marks, fixed labels) is a cheap first step before the catalog, but not a claim of centralization.
- **Process risks.** Executors stalled when planning state was oversized. Scrypath's PROJECT.md is 103 KB, MILESTONES.md 73 KB and RETROSPECTIVE.md 50 KB (STATE.md is 5 KB); plan a state-compaction step before v1.46 so subagents and executors do not read hundreds of KB each. Run the repository hygiene and contract scans locally before pushing large UI PRs (threadline's PR had six red CI runs).

## What mailglass taught us (read 2026-11-18; two surveys, nothing run; provenance in the playbook)

- **Cautionary tale.** Mailglass's brand v2 milestone (phases 179-183 plus 184, 24 plans, about 296 commits) is still blocked on verification gaps. Its evidence was bound to source bytes, so every CSS change superseded the captures and the after-review, and a cap of one hosted candidate turned cheap local defects (formatter, a `README.html` filename case, Node 18 vs a Playwright needing Node 20, Chromium refusing to launch on macOS) into a blocked milestone. Do not copy that structure.
- **Brand pin (copy into v1.46 phase 186).** Record the zip sha256 and size, a sha256 for every shipped asset with its license, and a closed list of owned directories where any unlisted file fails; the expected zip hash lives as a constant in the test; the offline verify is merge-blocking, the online re-download advisory; updates go through a script that refuses to write on mismatch. We already have the zip hash from the handoff. Decide the book version before the milestone starts (mailglass paid a gap plan for a mid-milestone pin move).
- **Before captures:** record them as review context only, not source-bound baselines. This is consistent with re-skin first.
- **Preflight checklist as a gate before any hosted candidate** (S15), and never cap attempts to a single candidate.
- **Scenario manifest (v1.47 phases 192 and 194).** One closed JSON catalog with a `proof_boundary` per row (story-only, story and connected route, connected-only, and a new `cli-text`), unrendered states as rows with a reason, one story variation per rendered row and the reverse, builders that raise on impossible ids, personas from one spec that feeds the seed, e2e and gallery, and one generic schema validator (not per-phase hand-listed shape tests).
- **Static stories mark themselves** ("Static rendering only. Actions are not connected.") with `data-scenario-id` and `data-state`, and a test asserts the marker.
- **Mix task text output is part of the catalog.** Mailglass has no CLI rules, but its email preview shows the pattern: host-owned content is shown unchanged inside branded chrome. For Scrypath, the Mix task labels stay unchanged and appear as `cli-text` rows with golden text fixtures, shown as a labeled `<pre>`, tested with `capture_io`. This is a proposal, not tried in mailglass.
- **Whole-task journey:** required LiveViewTest, advisory browser spec (S17); the proposed JOB-03 pilot follows this shape.
- **Model reviewer gate:** advisory only, calibrated with planted defects and a known-good item, quoted evidence checked as substrings, two or more judges. It costs about 45 judge runs per bundle change and sees only screenshot and aria text, so it never gates the required lane. Whether to build it at all is an owner question.
- **Copy:** cheapest first layers are a copy module with a required-state matrix per area, a golden table, render equality, and a status-word source scan with a per-file baseline and "detectors have teeth" tests; the AST literal lint (sigra's lessons) comes after. Mailglass shows the limit: even with those layers most screen copy stayed inline and a "Deferred" vs "Delayed emails" divergence survived.
- **Boundary:** add the missing test that `lib/` never mentions PhoenixStorybook, plus the publish allowlist diff and denylist; keep dev hooks out of any shipped assets module (mailglass leaked an inert storybook-hooks route into its tarball).
- **CI cost:** avoid cold-and-warm doubling and a per-story axe sweep in the required lane (mailglass: +314 s); make openers assert their target exists before waiting and keep waits under the server's sandbox lifetime (a 9-minute wait caused 44 failures).
- **State size again:** mailglass STATE.md is 113 KB and PROJECT.md 135 KB with no recorded stall, so the threadline stall risk is real but not universal; the compaction step is still cheap insurance.

## What exifcleaner taught us (read 2026-11-18; two surveys, nothing run; React/Electron specifics labeled in the playbook)

- **Order, fifth voice.** Exifcleaner went catalog-first with no restyle in v5.0 (7 phases, 35 plans, +61,071 lines, about 5 days with no product change), then restyled in v5.1 (still open; first restyled pixel 7 days after start; the real CSS change was a few hundred lines). Its survey's honest read: the evidence supports building the gates and the token seam first, not the full catalog first. The catalog did expose 370 findings (including 2 critical product bugs) before the restyle, but it showed the old skin. This supports our re-skin-first order and a small first catalog.
- **The big one: decouple pinned old-value tests before the re-skin.** Exifcleaner's palette phase needed 12 plans and 13 test-only prerequisite PRs, found one producer attempt at a time, because old tests pinned old values and a rule forbade changing a test in the same PR as the code it guards. Scrypath has exactly this class: the token mirror validator, contrast checker (21-token lock), motion gate, `surface_depth_token_contract_test` and e2e RGB constants. New v1.46 phase 187 below does this up front, with a scratch-tree dry run of the whole re-skin to project the failures (exifcleaner's spike projected 67 of 208 from one slice; actual was 208), and a named exception that lets a token-map row or data edit change a test in the same PR.
- **Token map with dispositions** (`adopt`, `derive`, `keep-platform`, `retire`, `local`), one entry per CSS custom property declared or used, with parity, hex-consistency and pin-match checks.
- **Contrast pair document:** pairs by backdrops by light, dark and system, layered overlays flattened, sealed baseline compared both ways, OS-dependent values as measured constants with a reason. Keep mailglass's per-block parity test and add this pair document; reuse mailglass's `contrast.ex` idea in Elixir.
- **Shrink-only findings register** (S19), computed-gap coverage grid with reasoned waivers (S20): adopt at small scale (8 to 10 subjects, 6 or 7 state classes). Dedupe findings by root cause. Zero gaps is declared coverage, not quality (65 percent waivers).
- **Fixtures that fold the real handlers** (C21) with an import gate and a mutation control; scenarios needing a mounted LiveView go to a wrapper story or the journey tier.
- **Journey proof honesty** (C23): story proofs only show a control exists and is reachable. Our pilot should chain LiveViewTest steps so each step's rendered output contains the next step's control, keep `unproven` plus a note tied to the register, and keep a keyboard-reachability check on rendered HEEx.
- **Test-server cache rule** (C24): any test that boots a second endpoint or asset watcher gets its own build and asset cache, port and output paths, with a mutation control. A retry is not a fix.
- **CI cap:** one source of truth, no strict under-N-seconds rule on noisy CI (exifcleaner's cap lived in three disagreeing places).
- **Human approval.** Exifcleaner's milestone is blocked on one named maintainer approval; the maintainer then changed layout twice after every automated gate was green, and a clipping check passed while 580 px filenames still truncated because it measured the wrong geometry. This is the clearest evidence that automated gates do not encode taste. It becomes an explicit owner decision below.

- **State size:** exifcleaner STATE.md is 226 KB, PROJECT.md 65 KB; no recorded stall but repeated checkpoint stops and state tools that clobbered STATE.md and MILESTONES.md by hand, matching our own note about state verbs wiping milestone fields.

## What playstead taught us (the failure case; read 2026-11-18; forensic and mechanics surveys; provenance in the playbook)

## What fablebook taught us (design-stage project; its own reply plus a verification subagent with experiments; provenance in the playbook)

- **Fablebook has no shipped re-skin or catalog**, so it gives no evidence on order. It is a design-stage replacement for phoenix_storybook, unreleased; Scrypath stays on phoenix_storybook (ADR 0001). Its value here is critique and boundary lessons.
- **Correction to our draft: do not depend on `__render_component__`.** It is accrue's choice. phoenix_storybook 1.5.0 never calls it; `function:` stories render public components and a `:page` story can return plain `~H` composed of production function components. The plan now extracts public `*_page/1` function components and uses `~H` page stories, with LiveViewTest for behavior and browser tests for layout (playbook C2). phoenix_storybook itself still depends on LiveView internals, so keep the spike's version-coupling check.
- **New verified boundary rule (C28).** Experiments on Elixir 1.19 show that `import`, `use` or `require` of a missing module fails at expansion even in a dead branch or behind a module-body `Code.ensure_loaded?`. The guard must run in the macro body outside the `quote`. Keep the storybook route in `dev_router.ex` (standalone only), keep the public `scrypath_ops_routes/2` macro untouched, return `quote(do: nil)` when the dependency is absent, and emit a loud `CompileError` when it is absent and the mount is reachable in a non-prod environment.
- **phoenix_storybook facts (C29).** 1.5.0 needs Phoenix 1.8.1+ and LiveView 1.1.21+ or 1.2, pulls the mdex Rust NIF (precompiled targets cover macOS arm64 and linux x86_64 in the cached version), and had three advisories published 2026-05-20 (critical RCE through the playground, high atom exhaustion, low PubSub hijack; the patched versions need confirming before we pin). The CSS, hooks and compile-time footguns are reported by others, not reproduced by anyone we surveyed, so they need a Scrypath benchmark in the spike.
- **Baseline guards (T18)** and a clarified CI cap policy (a hard timeout kills hangs; normal runs are not gated on a strict under-N rule). Fablebook's own non-UI CI shows the cost risk: core tests 12m10s, floor tests 11m29s, a 63.4 MB log.
- **Phase layout critique, accepted:** two infrastructure phases before the first visible screen was too many. v1.46 now merges ingest, pin and decouple into one capped phase so the visible re-skin is phase 187. README, HexDocs and website remain in v1.46 as separable phases after the ops re-skin and can move to the next milestone if v1.46 runs long (owner scope call).
- **Pilot gate critique, partly accepted:** the whole-job pilot's acceptance is real route state, persistence and transitions, keyboard use, theme and rendered geometry. Pixel-identical extraction is no longer a hard gate; where the existing preservation specs already cover a screen they run as an advisory parity check, and the gate is the whole-job test.
- **Process note:** a generated document that was hand-edited and drifted had to be reverted in fablebook; do not hand-edit generated views.

## What "verified" means in this plan (and what it does not)

With no human reviewer, a green catalog and passing checks establish: declared states and journeys are covered or waived with reasons; stated behavior holds on pinned data through the real LiveView (URL and filter state, next-step controls, persistence, side effects); both themes meet the declared contrast pairs; computed styles and rendered geometry (clipping, wrapping, overflow at the real container and widths) hold; copy comes from the catalog and avoids banned words; dev-only code is absent from the shipped package. They do not establish that the UI feels right, that a user will understand it, or that unlisted compositions are fine. Every phase summary must say which of these it proved and must not claim more. This matches the Phase 185 correction in AGENTS.md: subjective rendered critique stays nonblocking and is explicitly scoped; do not infer aesthetic or independent approval.

## Execution guardrails for every phase in v1.46 to v1.48 (proposed; owner to approve as AGENTS.md rules)

1. **Progress guard.** No phase is complete or continued unless its commits change the rendered UI of a whole screen or journey (or, in v1.47, produce a rendered story or a proven-identical extraction). A plan with no such change gets one commit and one day; a second consecutive one forces a stop-and-decide; an evidence-only phase is capped at 2 plans; no "proof of the proof".
2. **Loop breakers.** A full gate runs once per commit SHA; failures get a single-selector repro before any retry; hard wall-clock timeout, recorded as failure and not retried unchanged; at most 2 review-and-fix cycles per oracle; a stale receipt is a failed gate; at most 2 triage tasks per red gate, then quarantine with owner and date or revert; no capture from a dirty tree; environment aborts are classified as environment failures.
3. **Finite inventory.** Each milestone states a finite list of routes and states in scope before work starts. Adjacent areas wait for the next milestone.
4. **Retrospective on incomplete closeout** and a push-and-CI cadence.

## Key risks to design around

- Existing gates that fail on a recolor by design: token mirror validator, contrast checker (hard-locks 21 `--color-*` tokens), `surface_depth_token_contract_test` (dark floor #222831), motion gate (all transitions at most 240 ms; brand advance is 600 ms), Playwright RGB constants for violet, copper and the dark floor. Keep the structural and relational assertions; rewrite only the pinned-value ones.
- New palette contrast is fine (all text pairs at least 4.5:1, shapes at least 3:1). Thinnest margin: Retrying on the selected row, 4.58. Status colors have text pairs only; no computed fill pairs.
- phoenix_storybook `data_attribute` sets the theme on the sandbox container only, but 23 ops CSS rules are keyed on `html:not([data-theme="light"])` under `prefers-color-scheme: dark`. Stories in an OS-dark browser can render partly dark. Mirror the theme to `documentElement` in an iframe or sandbox script; model "System" as color-scheme emulation in the sweep.
- Whole LiveViews are not storybook-mountable as they are (see point 9). Control Room and Search health are closest; Failed sync, Search and Sync and index need extraction (Sync and index has about 35 assigns forming an implicit state machine).
- Compile guard is mandatory: deps compile in `:prod`, so any `use PhoenixStorybook` in `scrypath_ops/lib` breaks hosts without the dep. Add the dep to the boundary-test forbidden lists. The ops test endpoint can bind 0.0.0.0 with `PHX_SERVER=true`; never expose the playground there. Pin `~> 1.5`.
- Fixtures are process-global config today, so two states cannot render concurrently in one VM.
- Dead code to decide on: `ops_trail` renders nothing; 14 exports have no call sites; the non-`:ops` layout clause is unreachable. Recommend a coverage waiver with expiry, deletion as a separate cleanup.
- Brand scope limit: "your users' search screens use none of it." Only embedded `/admin/search`, the website, README, HexDocs and favicons are in scope.
- Fonts: the ops UI loads none today. Latin subsets are 53 KB (about 26 KB without Bricolage). Hanken and Sometype may lack arrow glyphs; host CSP may block mounted font paths (unverified).
- Cloak and cloak_ecto (no patched release; via optional sigra) keep `deep-quality` red until sigra ships without a hard `cloak_ecto` requirement; storybook's mdex NIF adds to the audited graph.
- Survey counts are heuristic (about 15 percent).
