# Cross-project notes from the Scrypath brand and catalog survey

Written 2026-11-18 by the Scrypath session for the sibling projects it surveyed (accrue, sigra, threadline, mailglass, exifcleaner, playstead; fablebook received an earlier handoff). Everything here is a hypothesis from another session: verify it against your own code, history and docs before acting, and record only what holds up, with provenance, in your own `.planning` knowledge base using your normal workflow. Do not change code on the basis of this file alone unless you confirm a real bug. Evidence grades: V verified by running or fetching the primary page, R read in files, W web (URL), U unverified.

Fuller material (read-only): `.planning/reference/BRAND-ADOPTION-PLAYBOOK.md` (rules with IDs, evidence and provenance), `.planning/research/brand-and-catalog/PROPOSAL.md` and `V1.46-PREP.md` in the Scrypath repo (`/Users/jon/projects/scrypath`). The playbook is the place to look up a rule ID.

## Shared: brand book, storybook and UI-workflow lessons that apply to every project

1. **Gate budget and progress guard (playbook S22, S23, S26):** across seven projects the failures that cost most were verification machinery outrunning visible change (one project: 14 of 246 commits in two weeks touched rendered UI), evidence bound to source bytes (supersession churn), a hard-coded cap with no deletion trigger, and planning state over about 100 KB. Consider a progress guard (no phase continues without a rendered change to a whole screen or journey; a second consecutive evidence-only plan forces a stop-and-decide), a cap on new required gates with a deletion trigger each, and a retrospective entry when a milestone closes incomplete.
2. **Token parity (playbook T1, T3, T12, T14):** one tracked token source, compared to the CSS in both directions over light, dark and system-dark, a deny-list of retired hexes with a planted-failure case, calibrated reject and accept cases through the same code path as the gate, and a browser check of settled computed colors across saved theme, switch, reload and navigation. A hand-copied palette with no parity check was the most common silent gap.
3. **Macro guard for an optional storybook route (V, experiment on Elixir 1.19):** `import`, `use` or `require` of a missing module fails at expansion even inside `if false`, inside `if Mix.env() == :dev`, in a never-called function body, and behind a module-body `Code.ensure_loaded?`. Safe: do the `Code.ensure_loaded?` check in the macro body outside the `quote` and return `quote(do: nil)` when absent (optionally `raise CompileError` when the dependency is absent and the mount is reachable in a non-prod env). Playbook C28.
4. **phoenix_storybook does not need `__render_component__` (R, source of 1.5.0):** `function:` stories render public components and a `:page` story's `render/1` can return plain `~H` composed of production function components. Playbook C2.
5. **phoenix_storybook advisories (V, github.com/advisories):** GHSA-55hg-8qxv-qj4p (unauthenticated RCE via HEEx injection in the playground, critical), GHSA-833p-95jq-929q (atom exhaustion, high), GHSA-mrhx-6pw9-q5fh (PubSub topic injection, low), all published 2026-05-20, all patched in 1.1.0. Confirm you are at or above 1.1.0, that the playground is dev-only, and that no test endpoint binds `0.0.0.0` with the storybook route mounted.

## Shared, secondary: also worth a quick glance (infrastructure, not the main point)

1. **Dependency advisories published recently (V, osv.dev):** ecto 3.14.2 and earlier (EEF-CVE-2026-118391, HIGH, unbounded query-cache growth from interpolated JSON paths; patched in 3.14.3, 2026-11-04) and plug up to 1.20.3 or any 1.19.x (EEF-CVE-2026-120287, MEDIUM, multipart framing not charged to `:length`; patched in 1.20.4, 2026-11-17; there is no 1.19.x fix, so a `~> 1.19.x` constraint must move to `~> 1.20.4`). If your nightly dependency audit is red, check these first. cloak 1.1.4 (EEF-CVE-2026-95105) and cloak_ecto 1.3.0 (EEF-CVE-2026-94206) have no patched release at all. `mix hex.audit` audits the whole lockfile, so `optional: true` does not hide them.
2. **`ubuntu-latest` is Ubuntu 26.04 since about Nov 11 to 12 (V, run logs).** Playwright 1.60.0 fails there at `npx playwright install --with-deps chromium` ("does not support chromium on ubuntu26.04-x64"). If a workflow floats on `ubuntu-latest` and installs Playwright browsers, pin `ubuntu-24.04` (and note that a BEAM or deps cache key containing the runner image version goes cold on every image change).
3. **GitHub Actions hygiene (V in Scrypath):** an `action-pins` check that matches only lines starting `- uses:` silently skips `uses:` lines under named steps; the repo default workflow permission may still be `write`; Dependabot may cover only the root manifest; a job-level `if` skip reports success, while a path-filtered workflow blocks merging if the check is required (W: GitHub required-checks troubleshooting). A boundary or storybook-leak test that runs only in an optional, path-scoped job is not a merge gate.

## accrue

The costs worth reconsidering: about 9,000 hand-written lines in `admin_catalog.ex`; a 2,970-case matrix and a roughly 17-minute required storybook job (consider advisory nightly for the full matrix and a generated PR selection manifest); evidence receipts committed at 46 MB (keep them as CI artifacts with a small digest manifest).

- `__render_component__` in storybook page stories is your own choice, not a phoenix_storybook requirement (playbook C2). Your router guard is correct (guard outside the `quote`) but lives in the shipped package; mailglass keeps the same guard in a demo-app helper.

## sigra

- `scrypath_ops` depends on `sigra ~> 1.5` as optional, but sigra 1.7.1 requires `cloak_ecto ~> 1.3` non-optional (V: hex.pm API; sigra `main` still does; tag v1.7.2 exists but is not on Hex; release PR #378 is open). cloak 1.1.4 and cloak_ecto 1.3.0 have no patched release, so Scrypath's fail-closed `deep-quality` stays red until sigra ships without a hard `cloak_ecto` requirement (or moves off AES-CTR). That is the one change in your repo that unblocks a sibling.
- Scrypath gates three actions through sigra (failed-work retry, index swap, saved-search delete) with seven outcomes (allowed, unverified identity, impersonating, step-up needed, sudo invalid, session malformed, integration unavailable) and no persistent blocked state in the UI. A pure decision function with typed reasons (your `Scope.resolve/3` shape) would let consumers render blocked states in stories without a running sigra; consider exposing one.
- Your gallery has no denied board (denial is covered end to end on seeded personas only); consider adding denied and revoked states to the state matrix.
- Your before catalog was text-only and guarded scope containment in the wording phase, not visual regressions in the visual phase (the visual phase was guarded by the token table, 30 contrast pairs and the frozen-name ratchet). The copy scanner is hand-rolled bytes (two fix rounds, six hand-listed attributes, no `.js`, negative-only); a `Code.string_to_quoted` plus tokenizer scan with attributes derived from `attr` declarations would remove those blind spots.

## exifcleaner

- v5.1's palette phase needed 13 test-only prerequisite PRs because old tests pinned old values and a rule forbade changing a test in the same PR as the code it guards. A named exception for a token-map row or data edit, role and threshold pins instead of value pins, and a whole-restyle scratch dry run (your spike projected 67 of 208 from one slice) would shorten the next one. Fablebook's ADR 0021 implements the same rule with an exception for added guard files (`A` allowed, `M` and `D` blocked).
- Coverage grid: 163 of 252 cells (65 percent) are waivers; the number measures declared coverage, not tests. Findings are fingerprinted per story, so about 5 root causes became 208 entries; consider deduping by root cause.
- The 400 s Storybook CI cap lives in three disagreeing places (`storybook-ci-budget.json` says 470 s, the roadmap uses 400 s, the workflow timeout is 10 minutes), and a run at exactly 400 s was rejected as "not strictly under". One source of truth, no strict under-N rule on noisy CI.
- Your milestone is blocked on one named maintainer approval; the maintainer changed layout twice (#451, #452) after every automated gate was green, and a clipping check passed while 580 px filenames still truncated because it measured the wrong geometry. Decide up front whether an explicit exception to the no-human rule exists.
- STATE.md 226 KB; state tools clobbered STATE.md and MILESTONES.md by hand.
