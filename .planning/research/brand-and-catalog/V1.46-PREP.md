Status: PREP NOTE for owner review, written 2026-11-18. It feeds, and does not replace, the downstream OpenGSD discuss, plan, execute and verify workflow. No phase plans live here. Nothing is started or approved.

Method: seven read-only research agents (token architecture; old-pin inventory with a measured recolor dry run; ingest, pin, fonts and packaging with a real `mix docs` build and Chromium probes; re-skin design and UX; delivery and governance; adversary on security, supply chain and CI; adversary on design, accessibility, product and adopters). Each weighed options through role lenses, used primary sources where it could, ran an adversarial pass, and gave one recommendation per decision. Labels: V verified by running or fetching the primary page, R read in files, W web (URL), U unverified or inferred. The owner's standing preferences applied: copy-paste over a dependency, small flat dependency trees, cheap checks before long suites, no human UAT, main stays green on lean required gates.

Related: [PROPOSAL.md](PROPOSAL.md) (whole-effort proposal), [the playbook](../../reference/BRAND-ADOPTION-PLAYBOOK.md) (rules with provenance), [ROLLING-ROADMAP.md](../../reference/ROLLING-ROADMAP.md).

### D9. Theme default and host contract

Recommendation (confidence 0.65-0.7): ops stays System-default; light default applies to the website, README and docs. Today an unset theme follows the OS; a bright default on a dark device would hit the on-call persona at night. The host contract: ScrypathOps owns styles for its shell and sets nothing outside it; the sheet loads only on ops routes (the demo does this through `ops_admin_path?`; the README requires the host to set `data-theme` on `<html>`); theme comes from `html[data-theme]`, else the OS; ops never forces light; accent override works through the existing daisyUI variables; variable names are stable, values may change; contrast-breaking overrides are the host's responsibility. Leak mechanics (V in built CSS, no host run): the shipped CSS includes Tailwind preflight (`*, ::after, ::before`), `:where(:root)` daisyUI theme variables and `:root,[data-theme]` base color and background, with themes named "light" and "dark" (the same `data-theme` values the Phoenix 1.8 generator uses, U); moving tokens to an ops root alone cannot fix this. Do not refactor isolation in the same sitting as the re-skin. Guards: a ratchet allowlist of unscoped selectors in compiled CSS; an ecommerce check that a non-ops route loads no ops stylesheet and computes no `--color-primary`; a host-override-wins fixture; a fixture host in light, dark and System with a sentinel host element whose computed style must not change, and CSP `font-src 'self'`; a settled-style check across six combinations (OS scheme times stored preference). A fully scoped `.ops-root` is deferred; a host reporting a leak would change that. Hosts using `class="dark"` get a one-line docs shim.
