## 2. Kickoff CI chore (`ecommerce-path` classifier)

**Why autonomous skips it.** It is in no phase: ROADMAP "Kickoff chore (not a phase) ... carries no requirement ID", REQUIREMENTS "Out of Scope" row, STATE "Pending Todos" (V). `autonomous.md` builds its queue only from roadmap phases with `phase_complete !== true` (`:175`).

**Facts that shape the choice** (V unless noted):
- Its value inside v1.47 is small: classifier skips browser lanes only for `.planning/`/docs/`*.md`-only PRs (`CI-EFFICIENCY.md` finding 2), and every v1.47 phase PR touches `website/`, `brand/`, `scrypath_ops/` or `examples/` and therefore must not skip. It pays off after the milestone (planning-only closeout and prep PRs).
- It must keep `workflow_wiring_test` green, report the required contexts as skipped-green like `ops-ui-path` (`ci.yml:357-373`), and not skip for `brand/`, `scrypath_ops/`, `examples/`, `scripts/ci/`, `lib/`, `mix.exs`, workflow files. It adds no required gate (same pattern as `ops-ui-path`), so the gate budget stays 8 of 12.
- Open Dependabot PR #132 changes `.github/workflows/ci.yml` and `website.yml` and is red in required `core` and `repository-contracts` because `workflow_wiring_test.exs:1041,1194,1239` hardcode the `upload-artifact` SHA (V: `gh pr view 132`). Phase 189 edits `website.yml` too (path filter, artifact upload), so #132 will conflict with it, and merge-on-green cannot clear #132 by waiting.

**Recommended tracking (so autonomous runs it).** Preferred: insert it as decimal phase **188.1 "CI path classifier"** with requirement **CI-01** (`/gsd-phase --insert 188 ...`, `wf/insert-phase.md`), mapped in REQUIREMENTS traceability, so it sorts before 189 (`autonomous.md:199` sorts numerically), gets its own PR, and `discover_phases` picks it up with `--only 188.1`. Smart-discuss's infrastructure detection (`ref/autonomous-smart-discuss.md` Sub-step 3, keywords "configuration", all-technical criteria) skips discuss with a minimal context, and it is not a frontend phase. Unverified (J): whether `phase.insert` accepts 188 now that v1.46 is archived; try it, and if it refuses use the fallback.
Fallback: make it **Plan 189-01** (requirement CI-01 added to Phase 189 and traceability, wave 1, no dependency), and fold the #132 SHA-relax into it (relax the hardcoded SHA to a pattern, which is exactly what #132 needs). Cost: it rides the 189 PR, which deploys the site, so a revert PR would revert both. Acceptable but second best.
Third option (cheapest, matches ROADMAP as written): run it by hand before starting autonomous, as a plain `chore(ci)` PR, since it is ~30 lines plus a test. Then no tracking change is needed, and the ledger entry in `CI-EFFICIENCY.md` records it.

**Pauses and outward actions in the chore:**
- PR creation, push, squash-merge on green: authorized. Default: proceed.
- First PR carries the four unpushed planning commits plus the `config.json` refresh (X2, X3); full 19-minute CI because the classifier does not exist yet. Accept.
- Local check first: `mix format --check-formatted`, `mix test test/mix/tasks/workflow_wiring_test.exs`, `act -l -W .github/workflows/ci.yml` (AGENTS "CI and CD efficiency"). Pinning `act` to a working Beam image is documented in `docs/releasing.md`; if `act` cannot run a lane, record that in the ledger and go on (nonblocking, not a stall).
- Sequence with #132: land the chore (or the SHA-relax) first, `gh pr update-branch 132`, merge #132 on green; otherwise it conflicts with 189's `website.yml` edit. #129 (examples npm): after the chore, `update-branch` and merge if green; if red for a real incompatibility, leave open and record (not a blocker).
- Not allowed: editing branch protection to require the new classifier (it is not a required context; the existing required contexts must keep reporting).
