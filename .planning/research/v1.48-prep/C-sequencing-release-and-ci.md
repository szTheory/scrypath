## 3. Sub-decision 2: ship a Hex release now?

Options:

1. **Docs-only 0.3.20 now.** Pros: the shipped tarball docs stop naming a task the package does not contain (since 0.3.18 `mix verify*` are not shipped: `CHANGELOG.md` 0.3.18 "Packaging"); there is precedent (0.3.19 was docs-only plus a hand-edited changelog); the pipeline is hardened (192 s publish, parity gate, ~19 min release PR CI). Cons: it needs a releasable commit (a `fix(docs):` title) and a hand-edited changelog; the tarball would differ from 0.3.19 only in two doc sentences plus `CONTRIBUTING.md` and `docs/releasing.md` (V above), so the Hex "what changed" signal is near zero; every release pings adopters' `mix hex.outdated`; and the actual harm is small because two of the four docs already carry the source-checkout qualifier. Semver view: pre-1.0 patch for a docs correction is legitimate and conventional, but it also trains adopters to read patches as "nothing to see", which weakens the signal for the next real one.
2. **Fix the docs on `main` now, release with the next library change.** Pros: zero release cost, no maintainer yes, no changelog noise; docs on `main` and (later) HexDocs converge at the next release. Cons: the two unhedged sentences stay wrong on hex.pm until then; v1.48 is UI-only (catalog foundation, `.planning/reference/ROLLING-ROADMAP.md`), and the next library work (v1.49 adopter features) is far, so "later" could be months unless a bug or a time-box forces it.
3. **`mix hex.publish docs` for 0.3.19.** Rejected: it fixes HexDocs only (not the tarball README or hex.pm page), and it breaks the rule that the only publish path is the tagged GitHub Actions workflow (`docs/releasing.md` intro and "Release parity gate"); it would make HexDocs differ from the tag.
4. **Bundle a harmless library improvement to justify a release.** Rejected: inventing library work to release violates the idle-train rule in AGENTS.md.

J recommendation: option 2, time-boxed. Fix the four docs on `main` in the housekeeping PR (qualify, do not delete: add "from a source checkout; not part of the Hex package" to `docs/operator-support.md:7`, `docs/jtbd-gap-map.md:78`, and tighten `guides/support-and-compatibility.md:131`). Ship a release when any of these happens: a library change merges (then it carries the docs for free), an outside adopter reports confusion, the maintainer wants to announce publicly, or 45 days pass. No maintainer yes is needed now; the yes is needed only when a release PR is merged.

Release-please footgun, from this repo's own history (V): `feat(ops-ui)` and `fix(ops-ui)` squash titles are releasable and open a Hex release PR whose notes describe a non-shipped app (0.3.19 needed a hand edit). `docs/releasing.md` "PR semantics on the train" tells people to use `fix:` for ordinary work, which is wrong for `scrypath_ops`, `examples/`, `website/`, `brand/`. Cheapest fix: write those PR titles as `chore(scope):` (a convention, zero code). Stronger fix, optional: `exclude-paths` per package in `release-please-config.json` (the manifest-releaser doc confirms the option: "exclude commits from that path from processing"). U: whether a commit touching both `lib/` and an excluded path still counts, and `.planning/`-only commits; prove it with a release-please dry run or a scratch fork before merging, because a misconfig silently suppresses a real release. Keep as a later XS item, not part of the sequence below.

## 4. Sub-decision 3: Dependabot #129 (axe-core 4.14.0)

The finding is real, not a false positive. axe's `label-content-name-mismatch` (WCAG 2.5.3 Label in Name, level A, impact serious; fetched from Deque's rule page) flags a widget with `aria-label` whose name does not contain its visible text. It matters to speech-input users: saying "click Nov 20, 2026" fails when the name is the ISO string. The rule only needs the name to CONTAIN the visible text, in order; best practice is to start with it.

Options:
- (a) Disable the rule in the e2e axe config: rejected (weakens what the check proves; the maintainer's rule "never weaken what a check proves just to go green").
- (b) Hold #129 at 4.11.3 with a Dependabot ignore: cheap but leaves a real, now-measurable defect and an ever-growing ignore list.
- (c) **Fix the markup** (recommended):
  - Timestamp: `aria-label={"Copy timestamp: #{@human}"}` at `ops_ui.ex:1350`. Contains the visible text; keeps the `Copy timestamp:` prefix, so `scrypath_ops/test/scrypath_ops_web/live/posture_live_test.exs:599` and `examples/scrypath_ecommerce/e2e/settings_layout.spec.ts:49` keep passing. The exact ISO value stays in `data-ops-timestamp-copy`, `datetime` and `title`.
  - Command hint: keep the `aria-label`, add the visible text: `aria-label="Go to… ⌘K"` at `ops_ui.ex:51`. Do NOT just delete the label: `app.css:458` hides the `<span>` text at narrow widths, leaving an icon-only button that needs a name. Update `scrypath_ops/test/scrypath_ops_web/ops_shell_contract_test.exs:174` (regex on the label) and `examples/scrypath_ecommerce/e2e/admin_shell_chrome.spec.ts:379` (`name: "Go to…", exact: true`) and `:492` (`toHaveAttribute("aria-label", "Go to…")`).
  - Whack-a-mole guard: 43 `aria-label` sites exist in `scrypath_ops/lib`; about eight sit on elements that also show text (`ops_ui.ex:249, 1166, 1492, 1501, 1607`, `failed_sync_live.ex:1239`, `search_live.ex:1829-1861`, `layouts.ex:70-80`). axe reported three nodes in one state; other states may surface more after the first fix. Audit those sites in the same PR and rerun the mounted lane.
- Cost: about 6 lines in `lib/`, about 4 assertion edits, one `ecommerce-mounted` cycle (about 15 min); unit-level check is `cd scrypath_ops && mix test` for the two test files. Dependabot rebase then merges #129 unmodified (never hand-edit the bot branch; `@dependabot rebase` or `gh pr update-branch` overwrites or is blocked).

Commit type matters: title it `chore(ops-ui):` (not `fix`), or it opens a Hex release PR (section 3).

## 7. Adversarial pass

- "Release now: it is free, fast, proven, and v1.48 may take months, so wrong docs sit on hex.pm that long." Partly survives: that is why the plan time-boxes at 45 days and names triggers. It does not survive as "release now", because two of the four docs already say "source checkout", the diff in shipped files is three trivial edits, and a docs-only patch dilutes the signal. If the maintainer prefers a visibly clean hex.pm page, option 1 is acceptable and cheap; this is a taste call, which is why confidence is 0.6.
- "Stopping CI work at the worker PR wastes the leverage of v1.48's roughly 11 plans; 5 minutes times about 15 PRs is over an hour." Survives with a trigger: the saving is real but capped (B alone is about 110 s; C needs a sharding scheme and adds flake surface to a required lane), minutes are free, and PRs overlap with work. The wait is paid per PR whether or not you look at it, so the trigger is measured wall time, not a feeling.
- "The aggregator job is a way around branch protection that quietly weakens it." True risk: a `needs` result of `skipped` or `cancelled` can read as green. If B or C is ever done, the aggregator must fail on anything but `success` (6 lines of shell, no `alls-green` dependency) and `workflow_wiring_test` needs a planted-failure case. This is why B and C are not "free" and are deferred.
- "Batching the vacuous-regex fix into the a11y PR can block #129 if the real assertion goes red." Survives with the stated fallback (split it out if red for an unclear reason). The alternative, a third PR and a third 19 min cycle for a one-liner, is worse on the value rule.
- "Use `fix(ops-ui)` like the docs say; chore hides it from changelogs." The `chore:` convention is what keeps non-library work from opening Hex release PRs; the doc's `fix:` advice predates `scrypath_ops` shipping separate surfaces. Update `docs/releasing.md` "PR semantics on the train" in PR 2 so the convention is written down.
- "Disable or downgrade the axe rule; it is experimental in WCAG 2.1 terms." Rejected: the rule maps to a Level A criterion (2.5.3) in WCAG 2.1, the finding is a genuine speech-input defect, and the project's standing rule is not to weaken a check to go green.
- What survives intact: no release now (time-boxed), fix markup rather than the rule or the version, ride the housekeeping on lanes already being paid for, defer structural CI work and the merge queue, leave website-only debt for the website-refresh prep.
