# v1.27 Gate Strategy

**Milestone:** v1.27 Adopter Contract Hardening  
**Date:** 2026-05-27  
**Status:** planning contract (implementation occurs in phases 99+)

## Objectives

1. Prevent install/support/proof drift from reappearing after reconciliation.
2. Keep release-train required checks lean and predictable.
3. Preserve the canonical adopter proof spine (`mix verify.adopter`).

## Planned Verify Aliases

| Alias | Purpose | Phase |
|-------|---------|-------|
| `mix verify.phase97` | Canonical contract + non-goal scope guard checks | 97 |
| `mix verify.phase98` | Surface-reconciliation consistency checks | 98 |
| `mix verify.phase99` | Aggregate drift gate for docs/proof/CI contract | 99 |
| `mix verify.adopter` | Canonical adopter proof spine (fast path) | cross-phase |

## Required PR Checks (feature-lane execution)

During v1.27 feature-lane PR work, required checks remain:

- `main-ci`
- `repo-hygiene`
- `release-truth`
- milestone trust gate coverage (`verify.phase99` once phase 99 lands)

## Non-blocking / advisory checks

- Live proof (`mix verify.adopter --live`) stays explicit and prerequisite-bound.
- Heavy integration/advisory suites remain non-blocking unless maintainers intentionally promote them.

## Failure Policy

- If contract surfaces disagree, PR fails on milestone trust gates.
- If live proof cannot run (env/service prerequisites absent), this is reported explicitly and does not silently pass as fast-proof success.
- If required PR checks are green but trust-gate coverage is missing for milestone scope, the phase is not complete.
